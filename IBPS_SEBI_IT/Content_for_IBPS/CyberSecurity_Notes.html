CS1 Introduction & the CIA Triad ›

Cyber security is the practice of protecting systems, networks, and data from digital attacks, unauthorized access, and damage. Almost every cyber security goal maps back to the CIA Triad:

  • Confidentiality — only authorized parties can access the information (protected via encryption, access control).
  • Integrity — data hasn't been altered or tampered with, either accidentally or maliciously (protected via hashing, checksums).
  • Availability — systems and data are accessible to authorized users whenever needed (threatened by DoS/DDoS attacks).
EXAM TIP

Almost every attack or defense mechanism can be classified by which part of the CIA triad it threatens or protects — a very common way exam questions are framed.

CS3 Common Cyber Attacks ›
  • Phishing — fraudulent emails/messages/sites tricking users into revealing sensitive data.
  • Spoofing — disguising communication (email, IP, website) to appear as if from a trusted source.
  • Man-in-the-Middle (MITM) — attacker secretly intercepts and possibly alters communication between two parties who believe they're talking directly to each other.
  • DoS / DDoS — flooding a system with traffic to make it unavailable to legitimate users (DDoS uses many distributed sources, often a botnet).
  • SQL Injection — inserting malicious SQL code into an input field to manipulate or extract data from a database.
  • Cross-Site Scripting (XSS) — injecting malicious scripts into web pages viewed by other users.
  • Brute Force Attack — systematically trying every possible password/key combination until the correct one is found.
  • Social Engineering — manipulating people (rather than systems) into divulging confidential information.
CS4 Cryptography Basics ›

Cryptography is the practice of securing information by transforming it into an unreadable format, reversible only with the correct key.

  • Plaintext — the original, readable message.
  • Ciphertext — the scrambled, unreadable form of the message after encryption.
  • Encryption — converting plaintext into ciphertext.
  • Decryption — converting ciphertext back into plaintext.
  • Key — the secret value that controls exactly how the encryption/decryption transformation is performed.

Two broad approaches exist, based on whether the same key is used for both encryption and decryption: Symmetric key cryptography and Asymmetric key cryptography — covered in detail next.

CS5 Symmetric Key Cryptography ›

In symmetric key cryptography, the exact same secret key is used for both encryption and decryption. Both the sender and receiver must already share this key privately before communicating.

Common Algorithms

DES (Data Encryption Standard — 56-bit key, now considered weak/obsolete), 3DES (Triple DES — applies DES three times for stronger security), AES (Advanced Encryption Standard — the current industry standard, key sizes of 128/192/256 bits), RC4 (a stream cipher, now considered insecure), Blowfish.

Worked Example — Alice sends Bob a secret message
1Alice and Bob already share one secret key, K (exchanged safely beforehand, e.g. in person or via a secure channel).
2Alice encrypts her plaintext message M using key K with an algorithm like AES: C = Encrypt(M, K).
3Alice sends the ciphertext C to Bob over the network (even if intercepted, it's unreadable without K).
4Bob decrypts it using the same key K: M = Decrypt(C, K), recovering the original message.

Pros & Cons

  • Pro: Fast and computationally efficient — well suited to encrypting large volumes of data.
  • Con: The key distribution problem — the shared secret key must somehow be exchanged safely beforehand, which is difficult to do securely over an open network.
CS6 Asymmetric Key Cryptography ›

In asymmetric key cryptography (also called public key cryptography), each party has a mathematically linked key pair: a public key (freely shared with everyone) and a private key (kept secret, never shared). Data encrypted with one key of the pair can only be decrypted with the other.

Common Algorithms

RSA (based on the difficulty of factoring large prime numbers — the most widely used), DSA (Digital Signature Algorithm), ECC (Elliptic Curve Cryptography — smaller keys, same security level, popular on mobile/low-power devices), Diffie-Hellman (used specifically for securely agreeing on a shared key over an open channel).

Worked Example — Alice sends Bob a secret message
1Bob generates a key pair: a public key Kpub-B and a private key Kpriv-B. He publishes Kpub-B openly — anyone can see it.
2Alice encrypts her message M using Bob's PUBLIC key: C = Encrypt(M, Kpub-B).
3Alice sends C to Bob. Anyone intercepting C cannot decrypt it — only Bob's matching private key can.
4Bob decrypts using his own PRIVATE key: M = Decrypt(C, Kpriv-B). No key exchange was ever needed beforehand.

Pros & Cons

  • Pro: Solves the key distribution problem entirely — the public key can be shared openly with no prior secret exchange needed.
  • Con: Computationally much slower/heavier than symmetric encryption — impractical for encrypting large volumes of data directly.

EXAM TIP

Real systems almost always combine both — this "hybrid" approach is a favourite exam concept. For example, HTTPS/TLS uses asymmetric encryption (RSA/ECC) only to securely exchange a temporary symmetric session key, then switches to fast symmetric encryption (AES) for the actual data of the session — getting asymmetric's easy key exchange AND symmetric's speed.

CS8 Hashing & Digital Signatures ›

Hashing

A hash function converts input data of any size into a fixed-size string (the "hash" or "digest"). Unlike encryption, hashing is one-way — it cannot be reversed to recover the original data, and is used to verify integrity rather than provide confidentiality. Common algorithms: MD5 (128-bit, now considered weak/broken), SHA-1 (also weakened), SHA-256 (part of the SHA-2 family, current standard).

Digital Signatures

A digital signature proves a message's authenticity and integrity using asymmetric cryptography, but in the reverse direction of encryption:

  1. The sender hashes the message, then encrypts that hash using their OWN private key — this encrypted hash is the "signature."
  2. The receiver decrypts the signature using the sender's public key, recomputes the hash independently, and checks the two match.

A digital certificate (issued by a trusted Certificate Authority, CA, as part of a PKI — Public Key Infrastructure) binds a public key to a verified identity, so others can trust that a given public key really belongs to who it claims to.

CS9 Security Protocols & Tools ›
  • SSL/TLS — cryptographic protocols securing data in transit; TLS is the modern successor to SSL, underlying HTTPS.
  • HTTPS — HTTP running over TLS, providing encrypted, authenticated web traffic.
  • SSH — encrypted protocol for secure remote login/administration.
  • Firewall — filters incoming/outgoing network traffic based on defined rules.
  • IDS / IPS — Intrusion Detection/Prevention Systems: monitor traffic for malicious activity; IDS alerts, IPS can actively block it.
  • VPN — creates an encrypted tunnel over a public network for secure, private communication.
  • 2FA / MFA — Two-Factor/Multi-Factor Authentication: requires more than one form of verification (e.g. password + OTP) to log in.

✓ Self-Test — Cyber Security & Cryptography

Score: 0/1000:00

1. Which part of the CIA Triad is most directly threatened by a DDoS attack?

A DDoS attack floods a system to make it unusable — directly attacking Availability.

2. Which malware type is standalone and spreads across a network on its own, without needing to attach to a host file?

A worm self-replicates and spreads independently; a virus needs a host file and human action.

3. In symmetric key cryptography, how many keys are used for both encryption and decryption combined?

Symmetric cryptography uses exactly one shared secret key for both encrypting and decrypting.

4. Which of these is a symmetric encryption algorithm?

AES is symmetric. RSA, ECC, and Diffie-Hellman are all asymmetric (public-key) approaches.

5. In asymmetric encryption, if Alice wants to send Bob a secret message, which key should she use to encrypt it?

Alice encrypts with Bob's public key — only Bob's matching private key can then decrypt it.

6. What is the main practical drawback of asymmetric encryption compared to symmetric encryption?

Asymmetric encryption is much slower than symmetric — that's exactly why real systems use it only to exchange a symmetric session key, then switch to symmetric encryption for the bulk data.

7. When creating a digital signature, the sender encrypts the message's hash using which key?

The sender signs using their OWN private key; anyone can then verify it using the sender's public key — proving it could only have come from them.

8. Which of these is true about hashing, as opposed to encryption?

Hashing is one-way — you can't recover the original input from the hash. It's used for integrity verification, not confidentiality.

9. HTTPS achieves both secure key exchange AND fast bulk data transfer by combining which two approaches?

This hybrid approach uses asymmetric crypto (RSA/ECC) just to exchange a symmetric session key, then AES (symmetric) handles the actual data — combining easy key exchange with speed.

10. Under India's IT Act 2000, which section specifically deals with the punishment for identity theft?

Section 66C specifically covers identity theft (fraudulent use of another's password/digital signature/unique ID). Section 66D covers cheating by personation, a related but distinct offence.
