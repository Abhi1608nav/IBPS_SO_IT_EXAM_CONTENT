CF2 CPU Architecture & Instruction Cycle ›

CPU Components

  • ALU (Arithmetic Logic Unit) — performs arithmetic and logical operations.
  • CU (Control Unit) — directs operation of the processor; fetches/decodes/executes instructions.
  • Registers — small, very fast storage inside the CPU:
    • AC — Accumulator: holds intermediate arithmetic/logic results.
    • PC — Program Counter: address of the next instruction.
    • IR — Instruction Register: holds the instruction currently being executed.
    • MAR — Memory Address Register: address to be accessed in memory.
    • MBR/MDR — Memory Buffer/Data Register: data being transferred to/from memory.
    • SP — Stack Pointer: top of the current stack.

Instruction Cycle

Fetch → Decode → Execute → (Store) — repeated for every instruction. Also called the FDE cycle.

Bus Types

BusCarriesDirection
Data busActual dataBidirectional
Address busMemory/IO addressUnidirectional
Control busControl signals (read/write, clock)Bidirectional

Architecture Types

Von Neumann architecture — single shared memory for both instructions and data (most modern PCs). Harvard architecture — separate memory/buses for instructions and data (used in many microcontrollers/DSPs, faster but more complex).

CF4 Number Systems & Conversion ›
SystemBaseDigits used

Quick Conversion Rules

  • Binary → Decimal: multiply each bit by 2position and sum. e.g. 1011₂ = 8+0+2+1 = 11₁₀
  • Decimal → Binary: repeated division by 2, read remainders bottom-up.
  • Binary → Hex: group bits in 4s from the right (each nibble = one hex digit).
  • Binary → Octal: group bits in 3s from the right.

Complements (used for representing negative numbers)

1's complement — invert all bits. 2's complement — 1's complement + 1; this is what modern computers actually use for signed integer arithmetic (subtraction becomes addition of the 2's complement).

✓ Self-Test — Computer Fundamentals

1. Which register holds the address of the next instruction to be executed?

PC (Program Counter) always holds the address of the next instruction. IR holds the current instruction being executed.

2. Which type of ROM can be erased and reprogrammed electrically, byte by byte, without removing it from the circuit?

EEPROM (Electrically Erasable PROM) can be erased/rewritten electrically. EPROM needs UV light; PROM is write-once.

3. The binary number 1101₂ is equal to which decimal value?

1101₂ = 8+4+0+1 = 13.

4. Which device is specifically used by banks to read the special characters printed at the bottom of a cheque?

MICR (Magnetic Ink Character Recognition) reads the magnetic-ink numbers on cheques — core banking-GK fact.

5. A translator that converts and executes a high-level program one line at a time, stopping immediately at the first error, is called a/an:

An interpreter translates and executes line-by-line. A compiler translates the entire program before execution.

6. Which malicious program self-replicates and spreads across a network without needing to attach itself to a host file?

A worm is standalone and self-propagates over a network; a virus needs a host file and human action to spread.

7. In an operating system, the technique where CPU time is divided among multiple users to give each the illusion of exclusive, simultaneous access is called:

Time-sharing OS slices CPU time across users/tasks. Multiprocessing means multiple physical CPUs.

8. Which of these best describes the relationship between the Internet and the World Wide Web (WWW)?

The Internet is the global network; the WWW is one application/service (hypertext documents) delivered over it — email, FTP etc. are other services on the same Internet.

DB1 Introduction: DBMS vs File System ›

Data = raw facts. Information = processed, meaningful data. A Database is an organised collection of related data; a DBMS (Database Management System) is the software that creates, manages and controls access to a database (e.g. MySQL, Oracle, SQL Server, PostgreSQL).

File System vs DBMS

AspectFile SystemDBMS
Data redundancyHighMinimised via normalization
Data integrityHard to enforceEnforced via constraints
Concurrent accessPoor/unsafeManaged via concurrency control
SecurityFile-level onlyFine-grained, user/role-level
Backup & recoveryManualBuilt-in mechanisms
Query capabilityProgrammer must write codeDeclarative queries (SQL)

Advantages of DBMS

Controlled redundancy, data integrity & consistency, data security, concurrent access control, backup/recovery, and data independence.

DB2 Architecture, Data Models & DBMS Languages ›

Three-Schema (ANSI-SPARC) Architecture

  • External level — individual user views of the database.
  • Conceptual level — the community/logical view — the whole database structure as seen by the DBA.
  • Internal level — physical storage structure (how data is actually stored on disk).

Logical data independence — ability to change the conceptual schema without changing external schemas/applications. Physical data independence — ability to change the internal/storage schema without changing the conceptual schema.

Data Models

ModelStructure
HierarchicalTree structure, parent-child (1:N) — e.g. IMS
NetworkGraph structure, records can have multiple parents (M:N)
RelationalData in tables (relations) of rows & columns — most widely used today
ER ModelConceptual design tool using entities & relationships (design stage, not storage)
Object-orientedData stored as objects, combining data + behaviour

DBMS Language Categories

CategoryFull formCommands
DDLData Definition LanguageCREATE, ALTER, DROP, TRUNCATE, RENAME
DMLData Manipulation LanguageSELECT, INSERT, UPDATE, DELETE
DCLData Control LanguageGRANT, REVOKE
TCLTransaction Control LanguageCOMMIT, ROLLBACK, SAVEPOINT
DISTINCTION

DROP removes the table structure and data entirely (DDL, cannot roll back in most DBs); DELETE removes rows but keeps the table structure (DML, can roll back); TRUNCATE removes all rows fast and resets identity, structure stays (DDL, generally no rollback).

DB3 ER Model ›

Building Blocks

  • Entity — a real-world object/thing (e.g. Employee). Entity set — collection of similar entities.
  • Attribute — property of an entity. Types: Simple (atomic, e.g. Age), Composite (divisible, e.g. Name → First+Last), Derived (computed, e.g. Age from DOB), Multivalued (multiple values, e.g. Phone numbers), Key attribute (uniquely identifies the entity).
  • Relationship — association between two or more entities. Degree: unary (1 entity), binary (2 entities — most common), ternary (3 entities).

Cardinality (mapping between entities)

CardinalityMeaningExample
1:1One entity relates to exactly one of anotherEmployee — manages — Department
1:NOne entity relates to many of anotherDepartment — has — Employees
M:NMany entities relate to many of anotherStudent — enrolls in — Courses

Participation constraint: Total (every entity instance must participate, shown as double line) vs Partial (participation is optional, single line).

Advanced ER Concepts

  • Generalization — bottom-up: combining lower-level entities into a higher-level generalized entity (Car + Truck → Vehicle).
  • Specialization — top-down: dividing a higher-level entity into lower-level specialized entities (Employee → Manager, Clerk).
  • Aggregation — treats a relationship itself as a higher-level entity so it can participate in further relationships.

ER Diagram Symbols

Rectangle = Entity · Ellipse = Attribute · Diamond = Relationship · Double ellipse = Multivalued attribute · Dashed ellipse = Derived attribute · Underline = Key attribute.

DB4 Relational Model & Keys ›

Relational Terminology

Relation = table · Tuple = row · Attribute = column · Domain = set of allowed values for an attribute · Degree = number of columns · Cardinality = number of rows.

Types of Keys

KeyDefinition
Super keyAny set of attributes that uniquely identifies a tuple (may include extra, unnecessary attributes)
Candidate keyA minimal super key — no attribute can be removed without losing uniqueness
Primary keyThe candidate key chosen to uniquely identify tuples; cannot be NULL
Alternate keyCandidate key(s) NOT chosen as primary key
Foreign keyAttribute in one table that references the primary key of another table — enforces referential integrity
Composite keyPrimary key made of two or more attributes together
Surrogate keyAn artificial key (e.g. auto-increment ID) with no business meaning

Integrity Constraints

  • Entity integrity — primary key value can never be NULL.
  • Referential integrity — a foreign key value must either match a primary key value in the referenced table or be NULL.
  • Domain constraint — every attribute value must come from its defined domain/data type.
  • Key constraint — no two tuples can have the same primary key value.
DB5 Normalization ›

Normalization removes redundancy and avoids anomalies by decomposing tables based on functional dependencies (an attribute B is functionally dependent on A if each value of A determines exactly one value of B, written A → B).

Anomalies (why we normalize)

  • Insertion anomaly — can't insert data without unrelated data also being present.
  • Update anomaly — same fact stored in multiple rows, risk of inconsistent updates.
  • Deletion anomaly — deleting one fact unintentionally deletes another needed fact.

Normal Forms

FormRule
1NFEvery attribute must hold only atomic (indivisible) values — no repeating groups/multivalued columns
2NFMust be in 1NF + no partial dependency (non-key attribute depending on only part of a composite primary key)
3NFMust be in 2NF + no transitive dependency (non-key attribute depending on another non-key attribute)
BCNF (Boyce-Codd NF)Must be in 3NF + for every functional dependency A → B, A must be a super key (stricter version of 3NF)
EXAM TIP

Remember the chain: 1NF (atomic values) → 2NF (no partial dependency, relevant only when PK is composite) → 3NF (no transitive dependency) → BCNF (every determinant is a candidate key). Questions often ask "which normal form removes transitive dependency" → 3NF.

Denormalization — intentionally introducing redundancy (reversing normalization) to improve read performance, common in data warehouses/reporting systems.

DB7 Transactions & Concurrency Control ›

ACID Properties

PropertyMeaning
AtomicityA transaction executes fully or not at all ("all or nothing")
ConsistencyA transaction takes the database from one valid state to another, preserving all rules/constraints
IsolationConcurrent transactions don't interfere with each other's intermediate state
DurabilityOnce committed, changes survive even a system crash

Transaction States

Active → Partially Committed → Committed, OR Active → Failed → Aborted.

Concurrency Problems (when isolation is weak)

  • Dirty read — reading uncommitted data from another transaction that may later be rolled back.
  • Lost update — two transactions update the same data, one update overwrites the other.
  • Unrepeatable read — re-reading the same row gives a different value within one transaction.
  • Phantom read — re-running the same query returns a different set of rows (new rows inserted by another transaction).

Concurrency Control Methods

Locking — Shared (S) lock allows concurrent reads; Exclusive (X) lock allows only one transaction to read/write. Two-Phase Locking (2PL) — a transaction acquires all locks first (growing phase), then releases them (shrinking phase), guaranteeing serializability. Timestamp ordering — transactions are ordered by timestamp instead of locks. Deadlock — two or more transactions wait indefinitely for each other's locks; resolved via detection (wait-for graph) or prevention.

DB8 Indexing & RAID ›

Indexing

An index is a data structure that speeds up data retrieval at the cost of extra storage and slower writes.

  • Primary index — built on the primary key; data is physically ordered by it.
  • Clustering index — built on a non-key field that determines the physical order of records.
  • Secondary index — built on a non-ordering field; does not affect physical order, can have many per table.
  • Most DBMSs implement indexes internally using a B-tree / B+ tree structure for fast, balanced lookups.

RAID Levels (Redundant Array of Independent Disks)

LevelTechniqueFault tolerance
RAID 0Striping (splitting data across disks)None — improves speed only
RAID 1Mirroring (exact copy on 2 disks)High — tolerates 1 disk failure
RAID 5Striping with distributed parityTolerates 1 disk failure

Data Warehouse

A large, subject-oriented, integrated, time-variant, non-volatile store of historical data used for analysis/reporting — distinct from an operational database used for daily transactions.

Distributed Database

Data is stored across multiple physical locations/nodes but appears as a single logical database to the user.

NoSQL (brief)

Non-relational databases designed for scale/flexibility: Document (MongoDB), Key-Value (Redis), Column-family (Cassandra), Graph (Neo4j). Typically follow BASE (Basically Available, Soft state, Eventually consistent) rather than strict ACID.

Codd's Rules

E.F. Codd (father of the relational model) defined 12 rules (numbered 0–12) that define what makes a DBMS truly relational — mainly tested as a fact ("who proposed the relational model" → E.F. Codd, 1970) rather than requiring the full list.

✓ Self-Test — DBMS

Score: 0/800:00

1. A minimal super key — one from which no attribute can be removed without losing the uniqueness property — is called a:

A candidate key is a minimal super key. The primary key is simply the candidate key chosen to identify rows.

2. A relation is in 2NF but a non-key attribute depends on another non-key attribute rather than directly on the primary key. Which normal form violation is this?

Non-key attribute depending on another non-key attribute = transitive dependency — removed to reach 3NF.

3. Which SQL clause is used to filter groups AFTER aggregation (e.g. departments with more than 5 employees)?

HAVING filters after GROUP BY/aggregation; WHERE filters individual rows before grouping and cannot use aggregate functions.

4. Which join returns all rows from the left table along with matching rows from the right table, filling unmatched right-side columns with NULL?

A LEFT JOIN keeps every row from the left table regardless of a match on the right.

5. Which ACID property guarantees that a transaction is either fully completed or fully rolled back, with no partial effect?

Atomicity = "all or nothing." Durability is about surviving crashes after commit; Isolation is about concurrent transactions not interfering.

6. A transaction reads a value written by another transaction that has NOT yet been committed, and that transaction is later rolled back. What is this problem called?

Reading uncommitted data that may vanish on rollback is a dirty read.

7. Which SQL command removes a table's structure AND all its data, and generally cannot be rolled back?

DROP (DDL) deletes the table structure and data entirely. DELETE (DML) removes rows but keeps the structure and can typically be rolled back.

8. In the ANSI-SPARC three-schema architecture, which level represents the physical storage structure of the data on disk?

The internal level deals with physical storage. External = user views; Conceptual = whole logical structure.

CN6 IP Addressing ›

IPv4

32-bit address, written as four 8-bit octets (e.g. 192.168.1.1), giving ~4.3 billion addresses.

ClassFirst octet rangeUsed for
A1–126Very large networks (few networks, many hosts)
B128–191Medium networks
C192–223Small networks (many networks, few hosts)
D224–239Multicasting
E240–255Reserved for research/experimental use

127.x.x.x is reserved for loopback (127.0.0.1 = localhost). Private (non-routable) IP ranges: 10.0.0.0–10.255.255.255 (Class A), 172.16.0.0–172.31.255.255 (Class B), 192.168.0.0–192.168.255.255 (Class C).

Subnet mask separates the network portion from the host portion of an address. CIDR notation (e.g. /24) states how many bits form the network part.

IPv6

128-bit address, written as 8 groups of hexadecimal digits separated by colons (e.g. 2001:0db8:85a3::8a2e:0370:7334). Created because IPv4's address space is exhausted.

CN9 Network Security Basics ›
  • Firewall — monitors and filters incoming/outgoing traffic based on security rules (hardware or software).
  • VPN (Virtual Private Network) — creates an encrypted tunnel over a public network for secure, private communication.
  • Proxy server — acts as an intermediary between client and the wider internet, can cache content/hide client IP.
  • Encryption — Symmetric (same key encrypts & decrypts, faster, e.g. AES) vs Asymmetric (public/private key pair, e.g. RSA, used in HTTPS/digital signatures).
  • Digital signature/certificate — verifies authenticity & integrity of a message/sender using asymmetric cryptography.
CN10 Error Detection & Flow Control ›

Error Detection

Parity check — adds one extra bit to make the count of 1s odd/even; catches single-bit errors only. Checksum — sender computes a value from the data, receiver recomputes and compares. CRC (Cyclic Redundancy Check) — polynomial-division based, more robust than parity, widely used in Ethernet.

Flow Control

Stop-and-wait — sender transmits one frame, waits for acknowledgement before sending the next (simple but slow). Sliding window — sender can transmit multiple frames before needing an acknowledgement, improving throughput.

✓ Self-Test — Computer Networks

Score: 0/800:00

1. Which network topology requires every node to be directly connected to every other node, giving n(n-1)/2 links for n nodes?

Mesh topology connects every node to every other node — most fault-tolerant but most expensive/complex to wire.

2. At which OSI layer does a switch primarily operate?

A switch forwards frames using MAC addresses — that's Layer 2, Data Link. A router works at Layer 3.

3. Which protocol is connection-oriented and guarantees reliable, ordered delivery of data?

TCP uses a 3-way handshake and acknowledgements for reliable delivery. UDP is connectionless and unreliable but faster.

4. Which port number is used by HTTPS?

443 is HTTPS (encrypted). Port 80 is plain HTTP.

5. An IPv4 address in the range 192.0.0.0–223.255.255.255 belongs to which class?

Class C (192–223) — used for small networks with many networks but few hosts each.

6. Which email protocol synchronizes messages and keeps them on the server (rather than downloading and removing them)?

IMAP keeps mail synced on the server (good for multi-device access). POP3 traditionally downloads and removes mail from the server.

7. Which switching technique breaks data into independently-routed units that are reassembled at the destination, and is what the modern Internet uses?

Packet switching is used by the Internet; circuit switching reserves a dedicated path (classic telephony).

8. Which error-detection method is polynomial-division based and is more robust than a simple parity check, widely used in Ethernet frames?

CRC uses polynomial division and is standard in Ethernet frame error-checking.
