OS1 Introduction & Core Functions ›

An Operating System is system software that acts as an intermediary between the user/applications and computer hardware. It has two broad roles: a resource manager (allocating CPU, memory, I/O devices fairly and efficiently) and an extended machine / interface (hiding hardware complexity behind a clean interface — CLI or GUI).

Core Functions

  • Process management — creation, scheduling, termination of processes.
  • Memory management — allocation/deallocation of main memory to processes.
  • File management — creation, deletion, organisation of files/directories.
  • I/O / device management — controlling and coordinating peripheral devices via drivers.
  • Security & protection — controlling access to resources, user authentication.
OS2 Process Management ›

A process is a program in execution (active); a program is a passive set of instructions stored on disk.

Process States

New → Ready → Running → (Waiting/Blocked ⇄ Ready) → Terminated

  • New — process is being created.
  • Ready — waiting to be assigned to a CPU.
  • Running — instructions are being executed by the CPU.
  • Waiting/Blocked — waiting for some event (e.g. I/O completion).
  • Terminated — process has finished execution.

PCB (Process Control Block)

A data structure maintained by the OS for every process, storing: process ID, process state, program counter, CPU registers, memory management info, scheduling info, and I/O status.

Schedulers

SchedulerRoleFrequency
Long-termSelects which jobs enter the "ready" pool from the job pool (admission control)Runs least frequently
Short-term (CPU scheduler)Selects which ready process gets the CPU nextRuns most frequently
Medium-termHandles swapping — temporarily removes processes from memory to reduce loadRuns in between

Context switching — saving the state (PCB) of the currently running process and loading the state of the next process, so the CPU can switch between them. This is pure overhead — no useful work is done during a context switch.

OS3 CPU Scheduling Algorithms ›

Scheduling Criteria

CPU utilization (keep CPU as busy as possible), Throughput (processes completed per unit time), Turnaround time (completion time − arrival time), Waiting time (time spent in ready queue), Response time (time from request until first response).

Algorithms

AlgorithmBehaviourPreemptive?
FCFS (First Come First Served)Processes run strictly in arrival orderNo
SJF (Shortest Job First)Process with the smallest burst time runs next; minimises average waiting timeCan be either (SRTF is preemptive SJF)
Priority SchedulingHighest-priority process runs first; risk of starvation for low-priority processes (solved via "aging")Can be either
Round RobinEach process gets a fixed time slice ("quantum"); cycles through ready queueYes — designed for time-sharing systems
EXAM TIP

SJF is provably optimal for minimising average waiting time — a frequently tested fact. Round Robin is the standard choice for interactive/time-sharing systems because of its fairness.

OS4 Threads & Multithreading ›

A thread is the smallest unit of CPU execution within a process — a "lightweight process." Multiple threads within one process share the same memory/address space but have their own registers and stack.

Process vs Thread

AspectProcessThread
MemoryOwn separate address spaceShares address space with sibling threads
Creation overheadHeavyLightweight, faster to create/switch
CommunicationNeeds IPC (inter-process communication)Direct — shared memory

User-level threads — managed by a library, unaware to the kernel (fast to create, but one blocking thread can block the whole process). Kernel-level threads — managed directly by the OS (slightly slower, but true parallelism across CPUs).

OS5 Process Synchronization ›

A race condition occurs when multiple processes/threads access shared data concurrently and the final result depends on the timing/order of execution. The critical section is the part of code where shared resources are accessed.

Requirements for a Correct Solution

  • Mutual exclusion — only one process in its critical section at a time.
  • Progress — if no process is in the critical section, one of the waiting processes must be allowed in without indefinite delay.
  • Bounded waiting — a limit exists on how many times other processes can enter before a waiting process gets its turn.

Semaphores

A semaphore is an integer variable used for signalling between processes, accessed only via wait() (P, decrement) and signal() (V, increment) operations.

TypeValuesUse
Binary semaphore (mutex)0 or 1Mutual exclusion — acts like a lock
Counting semaphoreAny non-negative integerControls access to a resource with multiple instances

Classic synchronization problems (conceptual, frequently named in exams): Producer-Consumer (bounded buffer), Readers-Writers, Dining Philosophers.

OS6 Deadlocks ›

A deadlock is a state where a set of processes are each waiting for a resource held by another process in the set, so none can proceed.

Four Necessary Conditions (Coffman conditions)

  1. Mutual exclusion — at least one resource must be held in a non-shareable mode.
  2. Hold and wait — a process holds one resource while waiting for another.
  3. No preemption — resources can't be forcibly taken away; only voluntarily released.
  4. Circular wait — a closed chain of processes, each waiting for a resource held by the next.

All four must hold simultaneously for deadlock to occur — breaking any one prevents it.

Handling Strategies

StrategyApproach
PreventionDesign the system so at least one Coffman condition can never hold
AvoidanceGrant resources only if the resulting state is "safe" — e.g. Banker's Algorithm
Detection & RecoveryAllow deadlock to occur, detect it (via resource-allocation graph), then recover (kill/rollback a process)
IgnoranceOstrich algorithm — assume deadlock is rare and simply ignore it (used by most general-purpose OSes)
OS7 Memory Management ›

Contiguous Allocation

Each process is allocated one contiguous block of memory. Partitioning can be fixed (equal/unequal pre-defined blocks) or variable/dynamic (sized to fit each process).

Fragmentation

  • Internal fragmentation — wasted space INSIDE an allocated block (allocated block is larger than needed).
  • External fragmentation — free memory exists but is scattered in small non-contiguous chunks, too small individually to satisfy a request.

Paging

Physical memory is divided into fixed-size frames; logical memory into equal-size pages. A page table maps each page to its frame. Paging eliminates external fragmentation (but can cause internal fragmentation in the last page).

Segmentation

Memory is divided into variable-size logical units called segments (e.g. code segment, data segment, stack segment) — matches how a programmer views a program, unlike paging's fixed physical division.

Virtual Memory

A technique allowing execution of processes that aren't fully loaded in main memory — using demand paging (pages loaded only when referenced). A page fault occurs when a referenced page isn't in memory and must be fetched from disk.

Page Replacement Algorithms

AlgorithmRule
FIFOReplace the page that has been in memory the longest
LRU (Least Recently Used)Replace the page that hasn't been used for the longest time — approximates optimal well in practice
OptimalReplace the page that won't be used for the longest time in the future — theoretical best, not implementable in practice (needs future knowledge)
OS8 File Management ›

File Allocation Methods

MethodHow it worksDrawback
ContiguousFile occupies a contiguous set of disk blocksFast access, but external fragmentation & difficult to grow files
LinkedEach block points to the next (like a linked list)No external fragmentation, but slow random/direct access
IndexedA separate index block stores pointers to all data blocks of the fileSupports direct access, extra overhead for the index block itself

Directory Structures

Single-level (one directory for all users — name conflicts), Two-level (separate directory per user), Tree-structured (hierarchical, most common — e.g. Windows/Linux file systems), Acyclic Graph (allows shared sub-directories/files via links).

OS9 Disk Scheduling ›

Disk scheduling decides the order in which pending I/O (read/write) requests to a hard disk are serviced, to minimise seek time (movement of the disk arm).

AlgorithmBehaviour
FCFSServices requests strictly in the order received — simple but can cause long seek times
SSTF (Shortest Seek Time First)Services the request closest to the current head position — can cause starvation of far-away requests
SCAN ("elevator" algorithm)Disk arm moves in one direction servicing requests, reaches the end, then reverses
C-SCANLike SCAN but after reaching one end, jumps back to the start without servicing on the return trip — gives more uniform wait times
LOOK / C-LOOKLike SCAN/C-SCAN but reverses direction as soon as there are no more requests ahead, rather than going all the way to the disk end

CO2 Microprocessor Basics (8085 Architecture) ›

A microprocessor is a single IC chip containing the CPU (ALU + Control Unit + registers) of a computer. The classic exam-reference microprocessor is the Intel 8085 — an 8-bit microprocessor.

8085 Registers

  • Accumulator (A) — 8-bit register, holds one operand and the result of ALU operations.
  • General-purpose registers — B, C, D, E, H, L (8-bit each; can pair as BC, DE, HL for 16-bit operations).
  • Flag register — holds status flags (Sign, Zero, Auxiliary Carry, Parity, Carry) set after ALU operations.
  • Program Counter (PC) — 16-bit, holds address of the next instruction.
  • Stack Pointer (SP) — 16-bit, points to the top of the stack in memory.

8085 has a 16-bit address bus (64 KB addressable memory) and an 8-bit data bus.

Microprocessor vs Microcontroller

AspectMicroprocessorMicrocontroller
ContainsOnly CPU on-chip; RAM/ROM/I-O are externalCPU + RAM + ROM + I/O all on a single chip
Use caseGeneral-purpose computing (PCs)Dedicated embedded control tasks (washing machines, ATMs)
Cost/complexityHigher, more powerfulCheaper, simpler, task-specific
CO3 Instruction Cycle & Pipelining ›

Each instruction executes via Fetch → Decode → Execute (the machine cycle). In the 8085, a machine cycle is further divided into T-states (clock cycles) — e.g. an "Opcode Fetch" machine cycle typically takes 4 T-states.

Pipelining

Pipelining overlaps the execution of multiple instructions — while one instruction is being decoded, the next is being fetched, and so on — improving overall instruction throughput (though not the latency of any single instruction).

Pipeline Hazards

  • Structural hazard — hardware resource conflict (two instructions need the same resource simultaneously).
  • Data hazard — an instruction depends on the result of a previous instruction still in the pipeline.
  • Control hazard — caused by branch instructions, where the next instruction to fetch isn't known until the branch resolves.

CO5 Arithmetic & Logic (ALU, Flags) ›

The ALU performs arithmetic (add, subtract, increment, decrement) and logical (AND, OR, NOT, XOR) operations. Subtraction is typically implemented as addition of the 2's complement, avoiding the need for separate subtractor hardware.

Common Status Flags

FlagSet when
CarryAn arithmetic operation produces a carry/borrow out of the most significant bit
ZeroThe result of an operation is exactly zero
SignThe result is negative (MSB = 1 for signed representation)
OverflowA signed arithmetic result is too large/small to fit in the available bits
ParityThe result has an even (or odd, per convention) number of 1 bits

Booth's algorithm — a technique for multiplying signed binary numbers efficiently in 2's complement form, reducing the number of add/subtract operations needed.

CO6 Cache & Memory Organization ›

Cache exploits the principle of locality: Temporal locality (recently used data is likely to be used again soon) and Spatial locality (data near recently used data is likely to be accessed soon too).

Cache Mapping Techniques

TechniqueHow it mapsTrait
Direct mappingEach memory block maps to exactly one specific cache lineSimple, fast, but more conflict misses
Associative (fully) mappingA memory block can go into any cache lineFlexible, fewer misses, but expensive/complex hardware (needs to search all lines)
Set-associative mappingCache divided into sets; a block maps to one specific set but can go anywhere within itPractical middle ground — most real CPUs use this

Cache Write Policies

Write-through — every write updates both cache and main memory immediately (simpler, more reliable, more memory traffic). Write-back — writes update only the cache; main memory is updated later when the cache block is evicted (faster, but more complex and riskier on failure).

CO7 I/O Organization & Interrupts ›

I/O Transfer Techniques

TechniqueHow it worksCPU involvement
Programmed I/OCPU continuously polls the device status and transfers data itselfHigh — CPU is busy-waiting, very inefficient
Interrupt-driven I/ODevice signals the CPU via an interrupt only when it's ready; CPU does other work meanwhileMedium — CPU still handles the actual data transfer
DMA (Direct Memory Access)A dedicated DMA controller transfers data directly between device and memory, bypassing the CPULowest — CPU is freed almost entirely for other tasks

Interrupts

Maskable interrupts — can be disabled/ignored by the CPU. Non-maskable interrupts (NMI) — cannot be disabled, reserved for critical events (e.g. power failure). Vectored interrupts — the interrupting device itself supplies the address of its interrupt-service routine; non-vectored — a fixed, predetermined address is used instead.

SE1 Introduction & SDLC ›

Software Engineering is the systematic application of engineering principles to design, develop, test, and maintain software. The SDLC (Software Development Life Cycle) is the standard sequence of phases a project moves through:

Requirement Analysis → Design → Implementation (Coding) → Testing → Deployment → Maintenance

  • Requirement analysis — gathering and documenting what the system must do.
  • Design — planning architecture, data structures, interfaces.
  • Implementation — actual coding based on the design.
  • Testing — verifying the software works correctly and meets requirements.
  • Deployment — releasing the software to users/production.
  • Maintenance — ongoing fixes, updates after release (typically the longest, costliest phase).
SE2 SDLC / Process Models ›
ModelApproachBest suited when
WaterfallStrictly sequential — each phase must finish before the next beginsRequirements are clear, stable, and well-understood upfront
Iterative/IncrementalBuilds the system in small increments, each adding functionalityRequirements are partially known, need feedback along the way

AgileShort iterations ("sprints"), continuous customer collaboration, embraces changing requirementsRequirements evolve, fast delivery and flexibility needed

EXAM TIP

Waterfall's biggest weakness: no going back once a phase is complete, and it doesn't accommodate changing requirements — this contrast with Agile is a favourite exam question.

SE3 Requirement Engineering ›

Types of Requirements

  • Functional requirements — WHAT the system must do (specific features/behaviours, e.g. "user can reset password").
  • Non-functional requirements — HOW WELL the system performs (quality attributes: performance, security, usability, reliability, scalability).

SRS (Software Requirements Specification)

A formal document that completely describes what the software system will do (and won't do), serving as a contract between developers and stakeholders/clients.

SE4 Software Design Principles ›

Coupling vs Cohesion

Coupling — degree of interdependence between different modules. Lower coupling is better (modules are more independent, easier to maintain/reuse). Cohesion — degree to which elements WITHIN a single module belong together / work toward a single purpose. Higher cohesion is better.

RULE OF THUMB

Good software design aims for low coupling, high cohesion — modules that are self-contained internally but loosely connected to each other.

Design Approaches

Structured design — top-down, function-oriented decomposition (e.g. using flowcharts, structure charts). Object-oriented design — organises the system around objects that bundle data and behaviour together (classes, encapsulation, inheritance).

Other Key Terms

Modularity — dividing software into separate, independent modules. Abstraction — hiding implementation detail and exposing only essential features.

SE5 Software Metrics & Estimation ›

Size Metrics

LOC (Lines of Code) — simplest size measure, but language-dependent and easy to game. Function Points — measures functionality delivered (inputs, outputs, inquiries, files, interfaces) independent of the implementation language — considered more objective than LOC.

COCOMO Model (Constructive Cost Model)

Estimates effort, cost, and schedule based on estimated project size (KLOC). Has three levels of detail: Basic, Intermediate, and Detailed COCOMO. Projects are classified into three modes:

  • Organic — small, simple, familiar/experienced team.
  • Semi-detached — medium size/complexity, mixed experience team.
  • Embedded — complex projects with tight constraints (hardware, regulations, real-time).
SE6 Software Testing ›

Verification vs Validation

Verification — "Are we building the product right?" (checking against design/specifications, static). Validation — "Are we building the right product?" (checking it meets user needs, dynamic/actual testing).

Testing Levels

LevelTests
Unit testingIndividual modules/functions in isolation
Integration testingInterfaces & interaction between combined modules
System testingThe complete, integrated system against overall requirements
Acceptance testingWhether the system satisfies business/user needs, performed by/for the client

Testing Types

TypeApproachCommon techniques
Black-box testingTests functionality without knowledge of internal codeEquivalence partitioning, boundary value analysis
White-box testingTests internal logic/structure with full code visibilityStatement coverage, branch coverage, path coverage

Alpha testing — performed by the internal development/QA team at the developer's site. Beta testing — performed by real end-users in their own environment, before final release.

SE8 Project Management Essentials ›

SCM (Software Configuration Management) — tracking and controlling changes to software artifacts (code, docs) throughout the project, typically via version control systems.

Risk management — identifying, analysing, and mitigating potential risks that could impact the project's schedule, cost, or quality.

Scheduling tools — Gantt chart (bar-chart visualising task timelines/overlaps) and PERT/CPM (network diagrams identifying task dependencies and the "critical path" — the longest sequence of dependent tasks determining minimum project duration).

SE9 Core Object-Oriented Concepts ›

Frequently bundled with SE questions since object-oriented design is a core SE topic.

  • Class — a blueprint/template defining properties (attributes) and behaviours (methods).
  • Object — a specific instance of a class.
  • Encapsulation — bundling data and the methods that operate on it together, restricting direct access to internal state ("data hiding").
  • Inheritance — a class (subclass) acquires properties/behaviours of another class (superclass), enabling code reuse.
  • Polymorphism — the ability for the same interface/method name to behave differently depending on the object calling it (e.g. method overloading and overriding).
  • Abstraction — exposing only essential features of an object while hiding internal implementation complexity.
