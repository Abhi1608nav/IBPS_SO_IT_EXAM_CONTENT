1 Data Link Layer & Multiple Access Protocols

How devices share a common communication medium — from wired Ethernet to wireless and satellite networks.

📋 Master Protocol Comparison Table

Protocol Medium / Environment Collision Strategy Operating Mechanism Max Efficiency Topic Tag
CSMA/CD Wired Ethernet (802.3) Detection Listen before transmit; detect collision via voltage spike; send jam signal; random backoff ~100% at low load; degrades under high load #MACSublayer
CSMA/CA Wi-Fi / Wireless (802.11) Avoidance Listen → wait DIFS → RTS/CTS handshake → transmit → ACK; random backoff on collision Lower than CSMA/CD due to overhead (RTS/CTS/ACK) #MACSublayer #Wireless
Token Passing Token Ring (802.5), FDDI Prevention Circular token passed; only token holder transmits; no collisions possible High & predictable at high load; poor at low load (token wait) #ControlledAccess
Pure ALOHA Satellite, early radio networks Uncontrolled Transmit anytime; if collision, wait random time & retry; vulnerable period = 2× frame time 18.4% (≈ 1/2e) #RandomAccess
Slotted ALOHA Satellite, shared channels Uncontrolled Time divided into slots; transmit only at slot start; vulnerable period = 1× frame time 36.8% (≈ 1/e) #RandomAccess

🔑 Key Formulas

Pure ALOHA: Smax = G·e−2G → 18.4%
Slotted ALOHA: Smax = G·e−G → 36.8%
Slotted ALOHA is exactly 2× more efficient than Pure ALOHA because the vulnerable period is halved.

⚡ CSMA/CD vs CSMA/CA

CSMA/CD — Can detect collisions because wired signals can be monitored (voltage changes). Used in Ethernet.
CSMA/CA — Cannot detect collisions wirelessly (hidden terminal problem). Must avoid them using RTS/CTS and ACKs. Used in Wi-Fi.
2 ICMP & Network Diagnostics

Internet Control Message Protocol — the error-reporting and diagnostic backbone of IP networks.

📋 ICMP Message Types Reference

Type Name Common Codes Function Triggered By
0 Echo Reply 0 Response to a ping request ping
3 Destination Unreachable 0 (Net), 1 (Host), 3 (Port), 13 (Comm. admin prohibited) Router/host cannot deliver packet to destination traceroute (final hop), port scans
4 Source Quench 0 Ask sender to slow down (flow control) Router congestion
5 Redirect 0 (Network), 1 (Host) Tell host to use a better router Router configuration change

🔍 How traceroute Works — Step by Step

┌──────────────────────────────────────────────────────────────────────────┐ │ traceroute destination.com │ └──────────────────────────────────────────────────────────────────────────┘ Round 1: Send 3 packets with TTL = 1 ┌────────┐ TTL=1 ┌─────────┐ │ Source │───────────→│ Router 1│ TTL→0 → Discards → Sends ICMP Type 11 └────────┘ └─────────┘ back to source with its IP Result: Hop 1 discovered ✓ Round 2: Send 3 packets with TTL = 2 ┌────────┐ TTL=2 ┌─────────┐ TTL=1 ┌─────────┐ │ Source │───────────→│ Router 1│───────────→│ Router 2│ TTL→0 → ICMP Type 11 └────────┘ └─────────┘ └─────────┘ Result: Hop 2 discovered ✓ Round N: Send 3 packets with TTL = N ...reaches Destination → Destination receives packet → If port unreachable → Sends ICMP Type 3 Code 3 (Port Unreachable) → This signals traceroute COMPLETE ✓
Key Insight: traceroute exploits the TTL field. Each round increments TTL by 1. Intermediate routers respond with ICMP Type 11 (Time Exceeded). The final destination responds with ICMP Type 3 (Destination Unreachable — Port), signaling the end.

3 Network Security Models & Architectures

Defensive strategies — from perimeter walls to zero-trust verification at every step.

🏰 Perimeter Defense

Philosophy: "Trust everything inside, block everything outside."

  • Firewalls at network boundary
  • Strong outer wall, weak interior
  • Once breached, attacker moves freely
  • Weakness: Insider threats, lateral movement

🔐 Zero Trust Architecture (ZTA)

Philosophy: "Never Trust, Always Verify" — every request is authenticated.

  • No implicit trust for any user/device
  • Micro-segmentation of network
  • Continuous verification & least privilege
  • Identity-based access control
  • Strength: Limits blast radius of breaches

🛡️ Defense in Depth (DiD)

Philosophy: Multiple overlapping layers of security controls.

  • Physical → Network → Host → App → Data
  • If one layer fails, others still protect
  • Firewalls + IDS + Encryption + MFA + Audits
  • Strength: Redundancy reduces single points of failure

🌐 Demilitarized Zone (DMZ)

Philosophy: Isolate public-facing services in a buffer zone.

  • Web servers, mail servers, DNS in DMZ
  • Between untrusted internet & trusted internal LAN
  • Two firewalls: screening + internal
  • Compromised DMZ ≠ compromised internal network

🏗️ Architecture Comparison

Model Core Philosophy Trust Model Key Mechanism Trade-off
Perimeter Castle & moat Trust inside, deny outside Firewalls, IDS at boundary Vulnerable to insider threats & breaches
Zero Trust Never trust, always verify Trust nothing, verify everything MFA, micro-segmentation, IAM Complex to implement; higher latency
Defense in Depth Layered security Multiple trust boundaries Overlapping controls at every layer Cost & management overhead
DMZ Buffer zone isolation Semi-trusted middle ground Dual-firewall, isolated subnet DMZ servers still exposed to attacks

6 Cryptography & Key Management

The mathematical foundation of digital security — encryption, signatures, and key exchange.

🔒 Asymmetric Encryption — Confidentiality

GOAL: Send a secret message to Bob Alice Bob ───── ─── 1. Gets Bob's PUBLIC key ─────────────────────────→ 2. Encrypts message with Bob's public key EBob-pub(M) = C 3. Sends ciphertext ────────→ 4. Decrypts with his PRIVATE key DBob-priv(C) = M Rule: Encrypt with receiver's PUBLIC key Decrypt with receiver's PRIVATE key

✍️ Digital Signature — Authentication & Non-Repudiation

GOAL: Prove Alice sent the message Alice Bob ───── ─── 1. Hashes message H(M) = digest 2. Encrypts hash with her PRIVATE key EAlice-priv(H(M)) = Sig 3. Sends M + Sig ─────────→ 4. Decrypts Sig with Alice's PUBLIC key → gets H(M)' 5. 6. Hashes received M → gets H(M) 7. 8. Compare: H(M)' == H(M)? ✓ Match = Authenticated ✓ Alice can't deny (non-repudiation)

🔢 Key Count Formulas

Symmetric Keys:
For N users → N(N−1) / 2 keys
Example: 10 users → 10×9/2 = 45 keys
100 users → 100×99/2 = 4,950 keys
Scales quadratically — impractical for large groups.
Asymmetric Keys:
For N users → 2N keys (N public + N private)
Example: 10 users → 2×10 = 20 keys
100 users → 2×100 = 200 keys
Scales linearly — highly scalable.

🔑 Key Concepts Summary

🔐 Confidentiality

Only authorized parties can read the data.

  • Achieved via encryption
  • Symmetric: same key (AES)
  • Asymmetric: public encrypts, private decrypts

✍️ Authentication

Verify the identity of the sender.

  • Achieved via digital signatures
  • Private key signs, public key verifies
  • Proves "who sent it"

🚫 Non-Repudiation

Sender cannot deny having sent the message.

  • Achieved via digital signatures
  • Only sender holds private key
  • Legal proof of origin
⚡ Quick Rule:
• Confidentiality → Encrypt with receiver's PUBLIC key
• Signature (Auth + Non-Repudiation) → Sign with sender's PRIVATE key
• Both together → Sign with sender's private key, then encrypt with receiver's public key
