🌐 Routing Algorithms

Types, scenarios, and when to use which

🎯 Exam Focus: SEBI frequently asks which routing protocol belongs to which category (IGP vs EGP), which algorithm it uses internally, and in what scenario each is best suited.

Classification of Routing Protocols

Protocol Type Algorithm Metric Max Hop Best Scenario
RIP (v1/v2) Distance Vector (IGP) Bellman-Ford Hop Count 15 Small networks (< 50 routers)
OSPF Link State (IGP) Dijkstra's (SPF) Cost (Bandwidth) No limit Large enterprise networks
EIGRP Advanced Distance Vector (IGP) DUAL (Diffusing Update) Composite (BW, Delay, Load, Reliability) No limit Cisco-only enterprise networks
BGP Path Vector (EGP) Path Vector (Policy-based) AS Path, Attributes No limit Internet backbone, inter-AS routing
IS-IS Link State (IGP) Dijkstra's (SPF) Cost No limit ISP networks, MPLS backbones

Detailed Breakdown

How it works: Each router maintains a table of distances (hop counts) to all destinations. Every 30 seconds, routers broadcast their entire routing table to neighbors. Uses Bellman-Ford algorithm.

Key Properties:

  • Maximum 15 hops (16 = unreachable)
  • RIP v1: Broadcast, no VLSM support
  • RIP v2: Multicast (224.0.0.9), supports VLSM & CIDR
  • RIPng: For IPv6
  • Slow convergence → Count-to-infinity problem
  • Mitigations: Split horizon, Route poisoning, Hold-down timers
🎯 When to use: Small office networks with < 50 routers where simplicity matters more than optimal routing. NOT suitable for large enterprise or ISP networks.

How it works: Each router builds a complete topology map (Link State Database) of the network using LSAs (Link State Advertisements). Then runs Dijkstra's algorithm to compute shortest paths.

Key Properties:

  • Uses areas (Area 0 = Backbone) for hierarchical design
  • Fast convergence (triggered updates, not periodic)
  • Supports VLSM, CIDR, authentication
  • Router types: Internal, ABR (Area Border Router), ASBR, Backbone
  • Cost = Reference Bandwidth / Link Bandwidth
  • Uses multicast 224.0.0.5 (all OSPF) and 224.0.0.6 (DR/BDR)
🎯 When to use: Large enterprise networks, campus networks, anywhere you need fast convergence and hierarchical design. Industry standard for IGP.

How it works: Exchanges routing information between Autonomous Systems (AS). Uses Path Vector algorithm — each route carries the complete AS path to prevent loops.

Key Properties:

  • iBGP: Within same AS | eBGP: Between different AS
  • Uses TCP port 179 (reliable delivery)
  • Policy-based routing (not purely metric-based)
  • Path attributes: AS_PATH, NEXT_HOP, LOCAL_PREF, MED
  • Slow convergence but extremely scalable
  • Runs the entire Internet
🎯 When to use: Internet backbone routing, multi-homed organizations connecting to multiple ISPs, inter-AS communication. NEVER used as IGP.

Idea: Repeatedly swap adjacent elements if they're in wrong order. Largest element "bubbles" to end each pass.

Execution Trace: [5, 3, 8, 1, 2]

Pass 1: [3,5,8,1,2] → [3,5,1,8,2] → [3,5,1,2,8] ← 8 bubbled
Pass 2: [3,5,1,2,8] → [3,1,5,2,8] → [3,1,2,5,8] ← 5 bubbled
Pass 3: [1,3,2,5,8] → [1,2,3,5,8] ← 3 bubbled
Pass 4: [1,2,3,5,8] → No swaps → Sorted! (Early termination)
void bubbleSort(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false;  // Optimization: early exit
        for (int j = 0; j < n - i - 1; j++) {
            if (arr[j] > arr[j+1]) {
                swap(arr[j], arr[j+1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // Already sorted
    }
}

Idea: Find minimum element, place it at beginning. Repeat for remaining unsorted portion.

Execution Trace: [5, 3, 8, 1, 2]

Pass 1: min=1 at idx 3 → swap(5,1) → [1,3,8,5,2]
Pass 2: min=2 at idx 4 → swap(3,2) → [1,2,8,5,3]
Pass 3: min=3 at idx 4 → swap(8,3) → [1,2,3,5,8]
Pass 4: min=5 at idx 3 → Already in place → [1,2,3,5,8]
void selectionSort(int arr[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++) {
            if (arr[j] < arr[minIdx])
                minIdx = j;
        }
        if (minIdx != i)
            swap(arr[i], arr[minIdx]);
    }
}

Idea: Like sorting cards in hand. Pick each element and insert it into its correct position in the sorted portion.

Execution Trace: [5, 3, 8, 1, 2]

Key=3: [3,5,8,1,2] ← 3 inserted before 5
Key=8: [3,5,8,1,2] ← 8 stays (already correct)
Key=1: [1,3,5,8,2] ← 1 inserted at beginning
Key=2: [1,2,3,5,8] ← 2 inserted between 1 and 3
void insertionSort(int arr[], int n) {
    for (int i = 1; i < n; i++) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];  // Shift right
            j--;
        }
        arr[j + 1] = key;  // Insert at correct position
    }
}

void merge(int arr[], int left, int mid, int right) {
    int n1 = mid - left + 1, n2 = right - mid;
    int L[n1], R[n2];
    
    for (int i = 0; i < n1; i++) L[i] = arr[left + i];
    for (int j = 0; j < n2; j++) R[j] = arr[mid + 1 + j];
    
    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        if (L[i] <= R[j]) arr[k++] = L[i++];
        else arr[k++] = R[j++];
    }
    while (i < n1) arr[k++] = L[i++];
    while (j < n2) arr[k++] = R[j++];
}

void mergeSort(int arr[], int left, int right) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        mergeSort(arr, left, mid);
        mergeSort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }
}

Idea: Pick a pivot, partition array so elements < pivot go left, > pivot go right. Recursively sort both halves.

Execution Trace (Last element as pivot): [10, 80, 30, 90, 40, 50, 70]

Pivot=70: [10, 30, 40, 50, 70, 90, 80] ← 70 at correct position
Left [10,30,40,50] Pivot=50: Already sorted
Right [90,80] Pivot=80: [80,90]
Result: [10, 30, 40, 50, 70, 80, 90]
int partition(int arr[], int low, int high) {
    int pivot = arr[high];  // Last element as pivot
    int i = low - 1;       // Index of smaller element
    
    for (int j = low; j < high; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(arr[i], arr[j]);
        }
    }
    swap(arr[i + 1], arr[high]);
    return i + 1;
}

void quickSort(int arr[], int low, int high) {
    if (low < high) {
        int pi = partition(arr, low, high);
        quickSort(arr, low, pi - 1);
        quickSort(arr, pi + 1, high);
    }
}
⚠️ Quick Sort vs Merge Sort — Key Differences:
  • Quick Sort: In-place, unstable, worst O(n²), better for arrays (cache-friendly)
  • Merge Sort: Not in-place (O(n) space), stable, always O(n log n), better for linked lists

Idea: Build a max-heap, repeatedly extract max element and place at end.

void heapify(int arr[], int n, int i) {
    int largest = i;
    int left = 2 * i + 1;
    int right = 2 * i + 2;
    
    if (left < n && arr[left] > arr[largest]) largest = left;
    if (right < n && arr[right] > arr[largest]) largest = right;
    
    if (largest != i) {
        swap(arr[i], arr[largest]);
        heapify(arr, n, largest);
    }
}

void heapSort(int arr[], int n) {
    // Build max heap
    for (int i = n / 2 - 1; i >= 0; i--)
        heapify(arr, n, i);
    
    // Extract elements one by one
    for (int i = n - 1; i > 0; i--) {
        swap(arr[0], arr[i]);  // Move max to end
        heapify(arr, i, 0);    // Heapify reduced heap
    }
}

🧠 Greedy vs Dynamic Programming

When to use which, overlapping problems, and exam tricks

🔵 Greedy Approach

  • • Makes locally optimal choice at each step
  • • Never reconsiders previous decisions
  • • Works when problem has Greedy Choice Property
  • • Also needs Optimal Substructure
  • • Faster: Usually O(n log n) or O(n)
  • • May NOT give optimal solution for all problems

🟣 Dynamic Programming

  • • Explores all possibilities systematically
  • • Overlapping subproblems — stores & reuses results
  • • Works with Optimal Substructure only
  • • Uses memoization (top-down) or tabulation (bottom-up)
  • • Slower: Usually O(n²) or O(n³)
  • • Always gives optimal solution

Head-to-Head Comparison

Criteria Greedy Dynamic Programming
StrategyTop-down, make immediate best choiceBottom-up or top-down with memoization
Revisiting decisionsNeverYes, explores all options
OptimalityNot guaranteedAlways guaranteed
Time ComplexityGenerally fasterGenerally slower
Space ComplexityUsually O(1) or O(n)O(n²) typically for table
Key RequirementGreedy Choice + Optimal SubstructureOptimal Substructure + Overlapping Subproblems

⚠️ Classic Exam Question: "For which problem does Greedy NOT give optimal solution?"
Answer is almost always: 0/1 Knapsack (NOT Fractional Knapsack).

Example: Capacity = 50, Items: {A: wt=10, val=60}, {B: wt=20, val=100}, {C: wt=30, val=120}
• Greedy by ratio: A(6.0) + B(5.0) + C(4.0) → Pick A+B = wt 30, val 160. Remaining capacity 20, can't fit C.
• DP optimal: B+C = wt 50, val 220 ← Better!

🔗 Linked Lists — Pseudocode

Singly, Doubly, and Circular with all operations

1. Singly Linked List

// Node Structure
struct Node {
    int data;
    Node* next;
    Node(int val) : data(val), next(nullptr) {}
};

// ============ INSERT AT BEGINNING ============
void insertAtHead(Node*& head, int val) {
    Node* newNode = new Node(val);
    newNode->next = head;
    head = newNode;
}

// ============ INSERT AT END ============
void insertAtTail(Node*& head, int val) {
    Node* newNode = new Node(val);
    if (head == nullptr) { head = newNode; return; }
    Node* temp = head;
    while (temp->next != nullptr) temp = temp->next;
    temp->next = newNode;
}

// ============ INSERT AT POSITION ============
void insertAtPos(Node*& head, int pos, int val) {
    if (pos == 1) { insertAtHead(head, val); return; }
    Node* temp = head;
    for (int i = 1; i < pos - 1 && temp; i++) temp = temp->next;
    if (!temp) return;  // Invalid position
    Node* newNode = new Node(val);
    newNode->next = temp->next;
    temp->next = newNode;
}

// ============ DELETE BY VALUE ============
void deleteNode(Node*& head, int key) {
    if (head == nullptr) return;
    if (head->data == key) {
        Node* temp = head;
        head = head->next;
        delete temp;
        return;
    }
    Node* temp = head;
    while (temp->next && temp->next->data != key) temp = temp->next;
    if (temp->next == nullptr) return;  // Not found
    Node* toDelete = temp->next;
    temp->next = toDelete->next;
    delete toDelete;
}

// ============ REVERSE ============
Node* reverse(Node* head) {
    Node *prev = nullptr, *curr = head, *next = nullptr;
    while (curr) {
        next = curr->next;    // Save next
        curr->next = prev;    // Reverse link
        prev = curr;          // Move prev forward
        curr = next;          // Move curr forward
    }
    return prev;  // New head
}

// ============ DETECT CYCLE (Floyd's) ============
bool hasCycle(Node* head) {
    Node *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next;        // Moves 1 step
        fast = fast->next->next;  // Moves 2 steps
        if (slow == fast) return true;
    }
    return false;
}

2. Doubly Linked List

// Node Structure
struct DNode {
    int data;
    DNode* prev;
    DNode* next;
    DNode(int val) : data(val), prev(nullptr), next(nullptr) {}
};

// ============ INSERT AT BEGINNING ============
void dllInsertHead(DNode*& head, int val) {
    DNode* newNode = new DNode(val);
    newNode->next = head;
    if (head) head->prev = newNode;
    head = newNode;
}

// ============ INSERT AFTER A GIVEN NODE ============
void dllInsertAfter(DNode* prevNode, int val) {
    if (!prevNode) return;
    DNode* newNode = new DNode(val);
    newNode->next = prevNode->next;
    newNode->prev = prevNode;
    if (prevNode->next) prevNode->next->prev = newNode;
    prevNode->next = newNode;
}

// ============ DELETE A NODE ============
void dllDelete(DNode*& head, DNode* delNode) {
    if (!head || !delNode) return;
    if (head == delNode) head = head->next;
    if (delNode->next) delNode->next->prev = delNode->prev;
    if (delNode->prev) delNode->prev->next = delNode->next;
    delete delNode;
}

// ============ REVERSE DOUBLY LL ============
DNode* dllReverse(DNode* head) {
    DNode* temp = nullptr;
    DNode* curr = head;
    while (curr) {
        temp = curr->prev;
        curr->prev = curr->next;  // Swap prev and next
        curr->next = temp;
        curr = curr->prev;  // Move to next (which is now prev)
    }
    if (temp) head = temp->prev;
    return head;
}

🌳 Trees & Traversal Conversions

BST operations, tree traversals, and exam-based conversion tricks

BST — Pseudocode

struct TreeNode {
    int data;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int val) : data(val), left(nullptr), right(nullptr) {}
};

// ============ INSERT ============
TreeNode* bstInsert(TreeNode* root, int val) {
    if (!root) return new TreeNode(val);
    if (val < root->data) root->left = bstInsert(root->left, val);
    else if (val > root->data) root->right = bstInsert(root->right, val);
    return root;
}

// ============ SEARCH ============
TreeNode* bstSearch(TreeNode* root, int key) {
    if (!root || root->data == key) return root;
    if (key < root->data) return bstSearch(root->left, key);
    return bstSearch(root->right, key);
}

// ============ FIND MIN ============
TreeNode* findMin(TreeNode* node) {
    while (node->left) node = node->left;
    return node;
}

// ============ DELETE ============
TreeNode* bstDelete(TreeNode* root, int key) {
    if (!root) return nullptr;
    if (key < root->data) root->left = bstDelete(root->left, key);
    else if (key > root->data) root->right = bstDelete(root->right, key);
    else {
        // Case 1: Leaf node
        if (!root->left && !root->right) { delete root; return nullptr; }
        // Case 2: One child
        if (!root->left) { TreeNode* temp = root->right; delete root; return temp; }
        if (!root->right) { TreeNode* temp = root->left; delete root; return temp; }
        // Case 3: Two children → Replace with inorder successor
        TreeNode* succ = findMin(root->right);
        root->data = succ->data;
        root->right = bstDelete(root->right, succ->data);
    }
    return root;
}

// ============ TRAVERSALS ============
void inorder(TreeNode* root) {   // LEFT ROOT RIGHT → Sorted order in BST
    if (root) { inorder(root->left); cout << root->data << " "; inorder(root->right); }
}
void preorder(TreeNode* root) {  // ROOT LEFT RIGHT
    if (root) { cout << root->data << " "; preorder(root->left); preorder(root->right); }
}
void postorder(TreeNode* root) { // LEFT RIGHT ROOT
    if (root) { postorder(root->left); postorder(root->right); cout << root->data << " "; }
}

🔄 Tree Traversal Conversions — EXAM MASTER GUIDE

🎯 Golden Rule: Inorder traversal of a BST always gives elements in sorted (ascending) order. This is the key to all conversions!
✅ Conversion 1: Preorder + Inorder → Build Tree → Find Postorder

Given: Preorder: [A, B, D, E, C, F] | Inorder: [D, B, E, A, F, C]

Step-by-step method (Exam Trick):

  1. First element of Preorder = ROOT → A is root
  2. Find A in Inorder → [D,B,E] A [F,C] → Left subtree has 3 nodes, Right has 2
  3. Left subtree: Preorder next 3 = [B,D,E], Inorder = [D,B,E]
    → B is root of left subtree. In inorder: [D] B [E] → D is left child, E is right child
  4. Right subtree: Preorder next 2 = [C,F], Inorder = [F,C]
    → C is root of right subtree. In inorder: [F] C [] → F is left child
  5. Postorder = Left + Right + Root → [D, E, B, F, C, A]
Tree Built:
        A
       / \
      B   C
     / \  /
    D   E F

Postorder: D E B F C A ✓
✅ Conversion 2: Postorder + Inorder → Build Tree → Find Preorder

Given: Postorder: [D, E, B, F, C, A] | Inorder: [D, B, E, A, F, C]

Step-by-step method:

  1. Last element of Postorder = ROOT → A is root
  2. Find A in Inorder → [D,B,E] A [F,C] → Left: 3 nodes, Right: 2 nodes
  3. Left subtree: Postorder first 3 = [D,E,B], Inorder = [D,B,E]
    → B is root (last of postorder). In inorder: [D] B [E]
  4. Right subtree: Postorder next 2 = [F,C], Inorder = [F,C]
    → C is root (last of postorder). In inorder: [F] C
  5. Preorder = Root + Left + Right → [A, B, D, E, C, F]
❌ Conversion 3: Preorder + Postorder → CANNOT uniquely determine tree!
⚠️ Critical Exam Point: Preorder + Postorder CANNOT uniquely construct a binary tree. You need Inorder as one of the pairs.

Why? When a node has only one child, you can't tell if it's a left child or right child from preorder+postorder alone.

Exception: If the tree is a Full Binary Tree (every node has 0 or 2 children), then preorder + postorder CAN uniquely determine the tree.

Valid combinations for unique tree construction:

  • ✅ Inorder + Preorder → Can build unique tree
  • ✅ Inorder + Postorder → Can build unique tree
  • ❌ Preorder + Postorder → Cannot build unique tree (ambiguous)
⚡ Quick Exam Tricks (No Coding Required)
Trick 1: First element of Preorder = Root
Trick 2: Last element of Postorder = Root
Trick 3: Inorder of BST = Sorted order
Trick 4: Preorder reversed ≠ Postorder (common trap!)
Trick 5: Inorder reversed = Reverse Inorder (RTL)
Trick 6: n nodes → n+1 null pointers in binary tree
Trick 7 (Direct Conversion without building tree):
If you know Preorder and Inorder, and need Postorder:
→ The root (first of preorder) will be LAST in postorder.
→ Recursively: postorder = left_postorder + right_postorder + root

Trick 8: For a BST, if given Preorder, Inorder is just the sorted version of preorder. Then apply conversion.

📐 Important Tree Properties (Formula Box)

• Max nodes at level L: 2^L
• Max nodes in tree of height H: 2^(H+1) - 1
• Min height of tree with N nodes: ⌈log₂(N+1)⌉ - 1
• Leaf nodes in full binary tree: (Internal nodes) + 1
• Null pointers in binary tree with N nodes: N + 1
• Edges in tree with N nodes: N - 1
• BST search (balanced): O(log n) | Worst (skewed): O(n)

void bfs(vector<vector<int>>& adj, int start, int V) {
    vector<bool> visited(V, false);
    queue<int> q;
    
    visited[start] = true;
    q.push(start);

        int curr = q.front(); q.pop();
        cout << curr << " ";

            if (!visited[neighbor]) {

                q.push(neighbor);
            }
        }
    }
}

Dijkstra's — Code

void dijkstra(vector<vector<pair<int,int>>>& adj, int src, int V) {
    priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> pq;
    vector<int> dist(V, INT_MAX);
    
    dist[src] = 0;
    pq.push({0, src});
    
    while (!pq.empty()) {
        int d = pq.top().first;
        int u = pq.top().second;
        pq.pop();
        
        for (auto& [weight, v] : adj[u]) {
            if (dist[u] + weight < dist[v]) {
                dist[v] = dist[u] + weight;
                pq.push({dist[v], v});
            }
        }
    }
}

Kruskal's MST — Code

// Union-Find (Disjoint Set)
int parent[1000], rank_[1000];

int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);  // Path compression
    return parent[x];
}

void unionSet(int x, int y) {
    int px = find(x), py = find(y);
    if (rank_[px] < rank_[py]) swap(px, py);
    parent[py] = px;
    if (rank_[px] == rank_[py]) rank_[px]++;
}

int kruskal(vector<tuple<int,int,int>>& edges, int V) {
    sort(edges.begin(), edges.end());  // Sort by weight
    int mstWeight = 0;
    for (int i = 0; i < V; i++) { parent[i] = i; rank_[i] = 0; }
    
    for (auto& [w, u, v] : edges) {
        if (find(u) != find(v)) {  // No cycle
            unionSet(u, v);
            mstWeight += w;
        }
    }
    return mstWeight;
}

📝 Numerical Example (All Algorithms)

Problem: Disk has 200 cylinders (0-199). Head is at cylinder 50. Moving toward higher cylinders.
Request queue: 82, 170, 43, 140, 24, 16, 190
Calculate total head movement for each algorithm.

1. FCFS (First Come First Serve)

Order: 50 → 82 → 170 → 43 → 140 → 24 → 16 → 190

Movement: |82-50| + |170-82| + |43-170| + |140-43| + |24-140| + |16-24| + |190-16|

= 32 + 88 + 127 + 97 + 116 + 8 + 174 = 642 cylinders

2. SSTF (Shortest Seek Time First)

Logic: Always go to nearest pending request

Order: 50 → 43 → 24 → 16 → 82 → 140 → 170 → 190

Movement: 7 + 19 + 8 + 66 + 58 + 30 + 20 = 208 cylinders

3. SCAN (Elevator) — Moving toward higher, disk end = 199

Logic: Go to end (199) servicing along the way, then reverse

Order: 50 → 82 → 140 → 170 → 190 → 199 → 43 → 24 → 16

Movement: (199-50) + (199-16) = 149 + 183 = 332 cylinders

4. C-SCAN — Moving toward higher, disk end = 199

Logic: Go to end (199), jump to 0, then service remaining

Order: 50 → 82 → 140 → 170 → 190 → 199 → 0 → 16 → 24 → 43

Movement: (199-50) + 199 + 43 = 149 + 199 + 43 = 391 cylinders

5. LOOK — Moving toward higher

Logic: Go to last request (190), then reverse (no need to go to 199)

Order: 50 → 82 → 140 → 170 → 190 → 43 → 24 → 16

Movement: (190-50) + (190-16) = 140 + 174 = 314 cylinders

6. C-LOOK — Moving toward higher

Logic: Go to last request (190), jump to first request (16), continue

Order: 50 → 82 → 140 → 170 → 190 → 16 → 24 → 43

Movement: (190-50) + (190-16) + (43-16) = 140 + 174 + 27 = 341 cylinders

Page Replacement Algorithms

FIFO (First In First Out):

Replace the oldest page. Simple but suffers from Belady's Anomaly (more frames → more page faults!)

Optimal (OPT/BEL):

Replace the page that won't be used for the longest time in the future. Cannot be implemented (needs future knowledge). Used as benchmark.

LRU (Least Recently Used):

Replace the page that hasn't been used for the longest time. Good approximation of Optimal. Implemented using stack or counter.

📐 Effective Memory Access Time (EMAT): 
EMAT = (1 - p) × memory_access + p × page_fault_overhead

Where p = probability of page fault

With TLB:
EMAT = hit_ratio × (TLB_access + memory) + miss_ratio × (TLB_access + 2×memory)
