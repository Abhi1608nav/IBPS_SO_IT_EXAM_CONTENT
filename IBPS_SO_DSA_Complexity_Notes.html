DS5 Hash Table ›
OperationAverage CaseWorst Case
SearchO(1)O(n)
InsertO(1)O(n)
DeleteO(1)O(n)

Worst case O(n) happens when many keys collide into the same bucket (e.g. a poorly designed hash function). Collision resolution techniques: Chaining (each bucket holds a linked list of colliding entries) and Open addressing (linear probing, quadratic probing, double hashing — all search for the next free slot within the table itself).

Space Complexity: O(n).

DS6 Binary Search Tree (BST) ›
OperationAverage CaseWorst Case (skewed)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)
Traversal (in/pre/post-order)O(n)O(n)
EXAM TIP

The worst case O(n) happens when the tree degenerates into a skewed shape (essentially a linked list) — e.g. inserting already-sorted data into a plain BST with no rebalancing.

Space Complexity: O(n) for the structure; traversal recursion uses O(h) stack space, where h is the tree's height (O(log n) balanced, O(n) worst case skewed).

DS7 Self-Balancing Trees (AVL / Red-Black) & B-Trees ›

AVL trees and Red-Black trees automatically rebalance after insertions/deletions, guaranteeing height stays O(log n) — eliminating the BST's worst-case skew problem entirely.

StructureSearchInsertDelete
AVL TreeO(log n)O(log n)O(log n)
Red-Black TreeO(log n)O(log n)O(log n)
B-Tree / B+ TreeO(log n)O(log n)O(log n)

These are all guaranteed worst-case O(log n) — unlike a plain BST. B-Trees/B+ Trees are specifically optimized for disk-based storage (databases, file systems) since each node holds many keys, minimizing costly disk reads.

Space Complexity: O(n) for all of these.

DS8 Heap (Binary Min/Max Heap) ›
OperationTime Complexity

Build heap from an unsorted arrayO(n)
COMMON TRAP

Building a heap from n elements is O(n), not O(n log n) — a classic exam trap. Although each of the n insertions could cost O(log n), the bottom-up "heapify" construction algorithm does the work more efficiently overall, giving a true O(n) bound.

Space Complexity: O(n).

COMMON TRAPS

Quick Sort's worst case is O(n²) — happens with a consistently bad pivot choice (e.g. already-sorted data with a naive first-element pivot). Merge Sort always needs O(n) extra space for the merge step, while Quick Sort and Heap Sort sort in-place (O(log n) and O(1) space respectively — the log n for Quick Sort is just recursion stack depth).

EXAM TIP

Stability means equal elements keep their original relative order. Stable: Bubble, Insertion, Merge, Counting, Radix, Bucket. Not stable: Selection, Quick, Heap — a frequently tested list to memorize both ways.

DS13 Recursion & Divide-and-Conquer ›

Fibonacci — naive recursionO(2ⁿ)O(n)

Tower of HanoiO(2ⁿ)O(n)

The space complexity of any recursive algorithm includes the call stack depth, even when no extra data structure is explicitly created — a detail often missed. Naive Fibonacci's O(n) space is exactly this call-stack depth, despite its explosive O(2ⁿ) time from redundant repeated calls.

Master Theorem (for divide-and-conquer recurrences)

For a recurrence of the form T(n) = a·T(n/b) + f(n), comparing f(n) against n^(log_b a) determines the overall complexity — this is how the O(n log n) bound for Merge Sort (a=2, b=2, f(n)=O(n)) is formally derived.

✓ Self-Test — DS & Algorithm Complexity

Score: 0/1200:00

1. What is the time complexity of accessing an element by index in an array?

Arrays support O(1) direct address computation — their defining advantage over linked lists.

2. What is the worst-case time complexity of search, insert, and delete in a plain (unbalanced) Binary Search Tree?

A plain BST degrades to O(n) in the worst case when it becomes skewed (essentially a linked list) — this is exactly what AVL/Red-Black trees fix.

3. Building a binary heap from an unsorted array of n elements takes:

The bottom-up heapify construction is O(n), not O(n log n) — a classic exam trap.

4. Which sorting algorithm has a worst-case time complexity of O(n²), despite an average-case of O(n log n)?

Quick Sort's worst case is O(n²), triggered by consistently poor pivot selection. Merge Sort and Heap Sort both guarantee O(n log n) even in the worst case.

5. Which of these sorting algorithms is NOT stable (does not preserve the relative order of equal elements)?

Quick Sort is not stable. Selection Sort and Heap Sort are also unstable; Merge, Insertion, and Bubble Sort are all stable.

6. Which single-source shortest path algorithm can correctly handle graphs with negative edge weights (and detect negative cycles), unlike Dijkstra's?

Bellman-Ford handles negative weights (O(V×E)); Dijkstra's requires all non-negative weights.

7. What is the time complexity of Binary Search on a sorted array of n elements?

Binary Search halves the search space each step, giving O(log n) — but it requires the data to already be sorted.

8. What is the space complexity used purely by the merge step of Merge Sort?

Merge Sort needs O(n) auxiliary space to merge sorted halves — unlike Quick Sort or Heap Sort, which sort in-place.

9. What is the time complexity of BFS or DFS traversal on a graph with V vertices and E edges?

Both BFS and DFS visit every vertex and edge exactly once (with an adjacency list), giving O(V + E).

10. In the average case, what is the time complexity of search, insert, and delete operations in a hash table?

Hash tables achieve O(1) average case, but degrade to O(n) worst case if many keys collide into the same bucket.

11. Which data structure representation is more space-efficient for a sparse graph (relatively few edges)?

An Adjacency List uses O(V+E) space — far better than O(V²) for sparse graphs where E is much smaller than V².

12. What is the time complexity of the naive (non-memoized) recursive Fibonacci algorithm?

Naive recursive Fibonacci recomputes the same subproblems repeatedly, giving exponential O(2ⁿ) time — memoization reduces this to O(n).
