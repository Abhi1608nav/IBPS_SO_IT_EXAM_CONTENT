BP1 Compilation & Execution Model ›
LanguageModelKey point
PythonInterpretedSource is compiled to bytecode internally then run by the Python Virtual Machine (PVM), line-by-line at runtime — no separate compile step for the user
C++CompiledSource is compiled directly into native machine code by a compiler (g++, MSVC) ahead of time — fastest execution, but platform-specific binaries

Java's bytecode + JVM model is what gives it platform independence — a very commonly tested distinction versus C++'s directly-compiled native binaries.

BP2 Variables & Data Types ›

Python is dynamically typed (no declaration keyword, type inferred at runtime and can change). C++ and Java are statically typed (type fixed at declaration, checked at compile time).

BP6 Functions & Methods ›
PYTHON
def add(a, b):
    return a + b
C++
int add(int a, int b) {
    return a + b;
}
JAVA
static int add(int a, int b) {
    return a + b;
}

Java methods must always live inside a class — there's no such thing as a free-standing function. C++ allows both free functions and class methods.

KEY DIFFERENCE

Function overloading (same name, different parameter types/count) is supported natively in C++ and Java, but not in Python — defining a function twice with the same name simply overwrites the earlier definition.

Python's built-in list is always dynamic and can hold mixed types. C++/Java's native arrays are fixed-size and single-typed — for dynamic behaviour you need vector (C++) or ArrayList (Java).

FH5 Automatic Resource Cleanup ›

Forgetting to close a file leaks a resource handle — each language has its own idiomatic way to guarantee closure automatically, even if an error occurs mid-way.

PYTHON
with open("data.txt", "r") as f:
    for line in f:
        print(line)
# file is automatically closed here
C++
{
    ifstream f("data.txt");
    // use f ...
} // f's destructor auto-closes it (RAII)
JAVA
try (BufferedReader br = new BufferedReader(new FileReader("data.txt"))) {
    String line;
    while ((line = br.readLine()) != null) { System.out.println(line); }
} // auto-closed at the end of try-with-resources
EXAM TIP

Python's with statement, Java's try-with-resources, and C++'s RAII (Resource Acquisition Is Initialization, via destructors) all solve the same problem — guaranteed cleanup — using three different language mechanisms. This three-way comparison is a common conceptual question.

1. Which C++ class is used specifically for reading from a file (input only)?

ifstream ("input file stream") is for reading; ofstream is for writing; fstream can do both.

Mode "a" (append) adds to the end of the file. Mode "w" overwrites/truncates existing content.

3. Which Java class is commonly wrapped around a FileReader to enable efficient line-by-line reading via readLine()?

BufferedReader wraps a FileReader and provides the convenient readLine() method along with buffering for efficiency.

4. Which C++ function is used inside a loop to read a file line by line into a string variable?

getline(stream, string) is the standard C++ way to read a line at a time from a file stream.

5. Which Python construct guarantees a file is automatically closed even if an exception occurs while it's open?

Python's with statement (context manager) guarantees the file is closed when the block exits, even on an exception.

6. What is the name of Java's mechanism that automatically closes a resource declared in the try's parentheses, once the try block finishes?

Try-with-resources (Java 7+) automatically calls close() on any resource declared in the try(...) parentheses.

7. In C++, the mechanism where a file stream's destructor automatically closes the file when the stream object goes out of scope is known by which acronym?

RAII (Resource Acquisition Is Initialization) ties resource lifetime to object scope — the destructor closes the file automatically.

8. Which Java class represents a file/directory path and provides methods like exists() and delete(), without itself reading or writing file content?

The File class represents a path/reference to a file or directory — used for existence checks, deletion, renaming, etc., not for reading/writing content.

try/catch/finally syntax, raising and catching exceptions, custom exception classes, and the checked-vs-unchecked distinction that's unique to Java.
EH1 What Is an Exception? ›

An exception is a runtime error/unexpected condition that disrupts the normal flow of a program (e.g. dividing by zero, accessing a missing file, an invalid array index). Exception handling lets a program detect these conditions and respond gracefully — logging the issue, retrying, or failing safely — instead of crashing abruptly.

EH2 try / catch / finally Syntax ›
PYTHON
try:
    x = 10 / 0
except ZeroDivisionError as e:
    print("Error:", e)
finally:
    print("Done")
C++
try {
    if (b == 0) throw runtime_error("Division by zero");
    result = a / b;
} catch (const runtime_error& e) {
    cout << "Error: " << e.what();
}
JAVA
try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Error: " + e.getMessage());
} finally {
    System.out.println("Done");
}
KEY DIFFERENCE

C++ has no finally block — cleanup is instead handled through RAII (destructors running automatically when objects go out of scope). Python and Java both support an explicit finally/finally block that always runs.

EH3 Raising / Throwing Exceptions ›
PYTHON
raise ValueError("Invalid input")
C++
throw invalid_argument("Invalid input");
JAVA
throw new IllegalArgumentException("Invalid input");

Python uses the keyword raise; C++ and Java both use throw. In Java, exception objects are always created with new.

EH4 Custom Exceptions ›
PYTHON
class MyError(Exception):
    pass

raise MyError("Something went wrong")
C++
class MyError : public exception {
public:
    const char* what() const noexcept override {
        return "Something went wrong";
    }
};
throw MyError();
JAVA
class MyException extends Exception {
    public MyException(String msg) { super(msg); }
}
throw new MyException("Something went wrong");

All three follow the same pattern: create a new class that inherits from the language's base exception type (Exception in Python/Java, std::exception in C++).

EH5 Catching Multiple Exception Types ›
PYTHON
try:
    ...
except (TypeError, ValueError) as e:
    print("Error:", e)
C++
try {
    ...
} catch (const invalid_argument& e) {
    ...
} catch (const out_of_range& e) {
    ...
}
JAVA
try {
    ...
} catch (IOException | SQLException e) {
    ...
}

Python groups multiple types in one except using a tuple. Java 7+ supports the same idea with the pipe | in one catch. C++ has no multi-type single-catch syntax — it always needs separate catch blocks per exception type.

EH6 Checked vs Unchecked Exceptions (Java-specific) ›

This distinction is unique to Java — Python and C++ don't enforce it.

  • Checked exceptions — must be either caught or declared with throws in the method signature; checked by the compiler (e.g. IOException, SQLException).
  • Unchecked exceptions (RuntimeException subclasses) — the compiler does NOT force you to catch or declare them (e.g. NullPointerException, ArithmeticException, ArrayIndexOutOfBoundsException).
EXAM TIP

In Python, every exception behaves like Java's "unchecked" kind — nothing is enforced by the interpreter at compile time (since there IS no separate compile-time check). C++ similarly has no checked/unchecked concept — any exception type can be thrown from anywhere without declaration.

✓ Self-Test — Exception Handling

Score: 0/800:00

1. Which keyword does Python use to manually trigger/raise an exception?

Python uses raise; C++ and Java both use throw instead.

2. Which of these three languages does NOT support a `finally` block, relying instead on RAII/destructors for guaranteed cleanup?

C++ has no finally block — cleanup relies on RAII (destructors firing automatically on scope exit). Python and Java both support finally.

3. In Java, an exception that must be either caught or declared with `throws` in the method signature, enforced by the compiler, is called a:

A checked exception (like IOException) must be handled or declared — enforced at compile time. RuntimeException subclasses are unchecked.

4. Which exception does Python raise when dividing a number by zero?

Python raises ZeroDivisionError specifically. Java's equivalent for integer division by zero is ArithmeticException.

5. In Java, catching two different exception types in a single catch block uses which syntax between the two type names?

Java 7+ multi-catch syntax uses a pipe: catch (IOException | SQLException e).

6. When creating a custom exception class in C++, which base class should it typically inherit from?

C++ custom exceptions typically inherit from std::exception, overriding its what() method.

7. Dereferencing a null pointer in C++ typically results in:

C++ has no built-in exception for null dereference — it's undefined behaviour, often crashing with a segfault, unlike Java's well-defined NullPointerException.

8. Which Java exception class is thrown when array access goes beyond the array's valid index range?

Java raises ArrayIndexOutOfBoundsException; Python's equivalent is IndexError, C++'s is std::out_of_range (when using bounds-checked .at()).
