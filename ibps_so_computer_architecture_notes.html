CPU Organization, Architecture & Instruction Cycle

The foundation everything else builds on — what's inside the CPU, how instructions actually get executed, and the registers that make it happen.

Basic components

ALU

Arithmetic Logic Unit — performs all arithmetic (add, subtract) and logical (AND, OR, NOT, comparisons) operations.

CU

Control Unit — directs and coordinates the operations of the entire CPU, generating control signals for fetch/decode/execute.

System Bus connects CPU, memory, and I/O — three distinct lines:

BusCarriesDirection
Data BusActual data being transferredBidirectional
Address BusMemory addresses to accessUnidirectional (CPU → memory)
Control BusControl signals (read/write, clock, interrupts)Both directions
Numerical trap: an n-bit address bus can directly address 2ⁿ memory locations. A 32-bit address bus → 2³² = 4 GB of addressable memory — a very frequently recycled question.

Von Neumann vs Harvard architecture

FeatureVon NeumannHarvard
MemorySingle shared memory for instructions + dataSeparate memory for instructions and data
BusSingle shared busSeparate buses — parallel access possible
BottleneckCan't fetch instruction and access data at the same time (the "Von Neumann bottleneck")No such bottleneck — faster
ComplexitySimpler, cheaperMore complex, costlier

The Instruction Cycle

instruction_cycle.txt
1

Fetch — the instruction at the address held in PC is fetched from memory into the IR; the PC is then incremented to point to the next instruction.

2

Decode — the Control Unit decodes the instruction in IR to determine the operation and the operands involved.

3

Execute — the ALU (or relevant unit) actually performs the operation.

4

Store — the result, if any, is written back to a register or memory.

Exam trap: the PC is incremented during the Fetch step — before execution even happens — not after Execute. This trips up a lot of "what happens when" questions.

Key registers

PC
Program Counter

Holds the address of the next instruction to fetch.

IR
Instruction Register

Holds the instruction currently being decoded/executed.

MAR
Memory Address Register

Holds the address of the memory location about to be accessed.

MDR
Memory Data Register

Holds data being transferred to or from memory (also called MBR).

ACC
Accumulator

Stores intermediate results of arithmetic/logic operations.

SP
Stack Pointer

Points to the top of the stack — critical for function calls/returns.

Instruction Set Architecture & Addressing Modes

How a CPU's instruction set is designed, and how instructions locate their operands.

CISC vs RISC

FeatureCISCRISC
Instruction setLarge, complex, variable-lengthSmall, simple, fixed-length
ExecutionInstructions can take multiple cyclesMostly single-cycle execution
Memory accessInstructions can directly access memoryLoad/Store architecture — only Load/Store instructions touch memory; the rest operate on registers
Control unitComplex, often microcodedSimpler, hardwired control
Compiler roleSimpler compiler — hardware does moreCompiler does more optimisation work
Examplesx86 (Intel, AMD)ARM, MIPS, RISC-V

Addressing modes

▸All addressing modes to know
▾
  • Immediate — the operand value is embedded directly in the instruction itself. Fastest — no memory access needed to fetch the operand.
  • Direct — the instruction contains the actual memory address of the operand.
  • Indirect — the instruction contains the address of a memory location that itself holds the address of the operand ("address of an address"). Slowest — needs two memory references.
  • Register — the operand sits directly in a CPU register.
  • Register Indirect — a register holds the address of the operand (in memory).
  • Indexed — effective address = base address + index register value; ideal for stepping through arrays.
  • Base Register — effective address = base register value + offset.
  • Relative — effective address = Program Counter + offset; the standard mode for branch/jump instructions.
Exam trap: Immediate addressing is the fastest (zero extra memory accesses); Indirect addressing is the slowest (needs an extra memory access just to resolve the operand's address). This speed ranking gets tested directly.

Memory Hierarchy & Cache

Why computers use several layers of memory instead of just one — and how cache bridges the speed gap.

The hierarchy

Registers
Fastest, smallest, most expensive per byte
Cache (L1/L2/L3)
Very fast, small, bridges CPU–RAM speed gap
Main Memory (RAM)
Moderate speed, moderate cost, volatile
Secondary Storage
SSD/HDD — slow, large, cheap, non-volatile
Tertiary / Backup
Slowest, largest, cheapest — tapes, archives

As you move down: speed decreases, capacity increases, and cost per byte decreases.

Cache memory & Locality of Reference

Why cache works

Cache exploits Locality of Reference — programs tend to access a small set of memory locations repeatedly over short periods.

Temporal
Locality

Recently accessed data is likely to be accessed again soon.

Spatial
Locality

Data near recently accessed data is likely to be accessed soon too.

Cache mapping techniques

TechniqueHow it worksTrade-off
Direct MappingEach memory block maps to exactly one specific cache lineSimple & fast, but more conflict misses
Fully AssociativeA memory block can go into any cache lineFewer conflicts, but expensive/slower to search
Set-AssociativeCache divided into sets; a block maps to one set but can sit anywhere within itA practical middle ground — most real CPUs use this

Cache write policies

PolicyBehaviour
Write-throughEvery write updates both cache and main memory simultaneously — consistent, but slower
Write-backWrites update only the cache; main memory is updated later when the block is evicted — faster, but risks inconsistency on a crash

RAM vs ROM types

SRAM

Static RAM — uses flip-flops, faster, more expensive, needs no periodic refresh. Used for cache.

DRAM

Dynamic RAM — uses capacitors, cheaper, slower, needs periodic refreshing. Used for main memory.

ROM typeBehaviour
PROMProgrammable once, cannot be changed afterward
EPROMErasable using ultraviolet light, then reprogrammable
EEPROMElectrically erasable and reprogrammable — the basis of modern flash memory

Virtual Memory

A technique that uses secondary storage to give programs the illusion of more main memory than physically exists — implemented via paging/segmentation, allowing programs larger than physical RAM to run.

I/O Organization & Pipelining

How the CPU talks to the outside world, and how it executes more than one instruction "at once".

I/O techniques

TechniqueHow it worksTrade-off
Programmed I/OCPU repeatedly checks (polls) device status in a busy-wait loopSimple, but wastes CPU cycles
Interrupt-driven I/ODevice signals the CPU via an interrupt only when it's readyCPU is free to do other work meanwhile — more efficient
DMAA dedicated DMA controller transfers data directly between device and memoryCPU is involved only at the start/end — fastest, minimal CPU overhead

Pipelining

Concept

Overlaps execution of multiple instructions — like an assembly line, different stages of different instructions run simultaneously to improve throughput.

Classic 5-stage instruction pipeline:

IF
ID
EX
MEM
WB

Instruction Fetch → Instruction Decode → Execute → Memory Access → Write Back

Pipeline hazards

HazardCause
Structural HazardTwo instructions need the same hardware resource at the same time (e.g. one memory unit for both instructions and data)
Data HazardAn instruction depends on the result of a previous instruction that hasn't completed yet
Control HazardCaused by branch instructions — the pipeline doesn't know which instruction to fetch next until the branch is resolved
Quick recall: Structural = hardware resource clash. Data = waiting on a previous result. Control = branching uncertainty. If a question mentions "branch" or "jump", it's a control hazard.
