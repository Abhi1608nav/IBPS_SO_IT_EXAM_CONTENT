CIA Triad, Information Security & Authentication

Every cyber security question ultimately traces back to one of these three goals — start here before anything else.

C

Confidentiality

Data is not disclosed to unauthorized parties.

Achieved via Encryption
I

Integrity

Data has not been altered by unauthorized parties.

Achieved via Hashing / Checksums
A

Availability

Authorized users can access data/systems when needed.

Achieved via Redundancy / Backups
The pairing to memorise: Confidentiality→Encryption, Integrity→Hashing, Availability→Redundancy/Backup. When a question maps a "combination of controls" to CIA, check each control against this pairing individually rather than guessing the whole option at once.

Information Security — beyond CIA

Some questions extend the triad with two more pillars:

  • Authenticity — confirming data/identity genuinely comes from the claimed source
  • Non-repudiation — the sender cannot later deny having sent a message (enabled by digital signatures)

Authentication

Exam trap: Authentication = verifying who you are. Authorization = verifying what you're allowed to do, and always happens after authentication. These two are swapped constantly in options.
FactorCategoryExample
Something you knowKnowledge factorPassword, PIN, security question
Something you havePossession factorOTP token, smart card, authenticator app
Something you areInherence factorFingerprint, retina scan, face recognition

Multi-Factor Authentication (MFA) combines two or more of these factors — e.g. password + OTP — significantly harder to compromise than any single factor alone.

Cyber Attacks & Malware

Two overlapping lists — attacks are the *techniques*, malware is a *category of malicious software* often used to carry them out.

Common cyber attacks

▸Attack types to know
▾
  • Phishing — fraudulent communication (usually email) tricking a user into revealing sensitive information
  • DoS / DDoS — flooding a system with traffic to make it unavailable to legitimate users (a direct attack on Availability)
  • Man-in-the-Middle (MITM) — attacker secretly intercepts, and possibly alters, communication between two parties
  • SQL Injection — malicious SQL code inserted through an input field to manipulate a database
  • Brute Force — systematically trying every possible password/key combination
  • Social Engineering — manipulating people (not systems) into breaking normal security procedures
  • Spoofing — impersonating a trusted source (IP spoofing, email spoofing, DNS spoofing)
  • Zero-day attack — exploits a vulnerability before a patch/fix exists for it

Malware types

MalwareBehaviour
VirusAttaches to a host program/file; needs a host and user action to spread
WormSelf-replicating; spreads independently across a network, no host file or user action needed
Trojan HorseDisguised as legitimate software; does not self-replicate
RansomwareEncrypts victim's files, demands payment for the decryption key
SpywareSecretly monitors and collects user activity/data
AdwareDisplays unwanted advertisements, often bundled with free software
RootkitGains privileged (root/admin) access while actively hiding its own presence
KeyloggerRecords keystrokes to steal credentials and sensitive input
The single most repeated exam distinction: a Virus needs a host file + user action to spread; a Worm is self-replicating and spreads on its own across a network. If the question says "spreads without any user intervention" → it's a Worm.

Firewalls, Antivirus & IDS/IPS

The defensive counterparts — what actually stands between an attack and your system.

Firewall types

TypeHow it works
Packet-filteringInspects only packet headers (IP address, port) — fast, but no awareness of connection context
Stateful InspectionTracks the state of active connections for more context-aware filtering decisions
Proxy / Application-level gatewayActs as an intermediary, inspecting traffic at the application layer
Circuit-level gatewayVerifies the TCP handshake is legitimate without inspecting the packet content itself
Next-Generation Firewall (NGFW)Combines traditional filtering with deep packet inspection and intrusion prevention

Antivirus detection methods

Signature-based

Matches files against a database of known malware signatures. Fast and reliable for known threats, but blind to brand-new (zero-day) malware.

Heuristic-based

Analyses behaviour and code structure to catch previously unseen malware. Can catch zero-days, but risks more false positives.

IDS vs IPS

Exam trap: An IDS (Intrusion Detection System) only monitors and alerts — it does not block anything, exactly as its name says. An IPS (Intrusion Prevention System) goes further and actively blocks the detected threat. If an option implies an IDS "stops" or "prevents" an attack, it's incorrect.
TypeScope
NIDSNetwork-based — monitors traffic across the network
HIDSHost-based — monitors activity on a single system/host

Symmetric vs Asymmetric Key Cryptography

The highest-yield sub-topic in Cyber Security — nearly every paper has at least one direct question here. Covered in full depth with worked examples.

Symmetric Key Cryptography

The same key is used for both encryption and decryption.

  • Fast — ideal for encrypting large volumes of data
  • Key Distribution Problem — both parties must securely share the one secret key beforehand; if it's intercepted, everything is compromised
DES3DESAESRC4Blowfish

Asymmetric Key Cryptography

Uses a mathematically linked key pair: a Public key (shared openly) and a Private key (kept secret).

  • What one key encrypts, only the other key can decrypt
  • Slower — 100-1000× more computationally expensive than symmetric, so not used for bulk data
  • Solves the key distribution problem entirely — no secret ever needs to be shared
RSADSAECCDiffie-Hellman

Worked example — Symmetric encryption

symmetric_example.txt
1

Alice and Bob agree on a shared secret key K over a secure channel (e.g. in person, or via a pre-shared setup).

2

Alice encrypts her message M = "MEET AT 5PM" using AES with key K → produces ciphertext C.

3

Alice sends C to Bob over an ordinary, possibly insecure, network.

4

Bob decrypts C using the same key K → recovers the original message M.

⚠

Risk: if key K is intercepted at step 1, an attacker can decrypt every future message — this is exactly the key distribution problem.

Worked example — Asymmetric encryption (confidentiality)

asymmetric_example.txt
1

Bob generates a key pair: Public key Kpub-B and Private key Kpriv-B, and publishes Kpub-B openly for anyone to see.

2

Alice wants to send Bob a confidential message M. She encrypts it using Bob's public key: C = Encrypt(M, Kpub-B).

3

Alice sends C to Bob over the open network — no secret needed to be shared in advance.

4

Only Bob's matching private key can decrypt it: M = Decrypt(C, Kpriv-B).

✓

Even if an attacker intercepts C, it's useless without Bob's private key — which never travelled anywhere.

Digital Signature — the reverse use of asymmetric keys

For confidentiality, the sender encrypts with the receiver's public key. For a digital signature (authenticity + integrity + non-repudiation), the direction flips — the sender signs with their own private key:

digital_signature.txt
1

Alice computes a hash of her message: H = Hash(M).

2

Alice encrypts that hash with her own private key: Signature S = Encrypt(H, Kpriv-A). This is the "signing" step.

3

Alice sends both M and S to Bob.

4

Bob decrypts S using Alice's public key to recover H, and independently computes Hash(M) himself.

✓

If the two hashes match: the message is authentic (only Alice's private key could produce a valid signature) and unaltered (integrity) — and Alice cannot later deny sending it (non-repudiation).

Hybrid cryptography — how HTTPS/TLS actually works

Real-world application

Every HTTPS website uses both: asymmetric cryptography runs once, at the start of the connection, purely to securely exchange a random symmetric session key. From then on, the much faster symmetric cryptography (using that session key) handles all the actual data transfer for the rest of the session — combining asymmetric's secure key exchange with symmetric's speed.

How RSA actually works (simplified textbook example): Pick two primes p=3, q=11 → n = p×q = 33, φ(n) = (p−1)(q−1) = 20. Choose public exponent e=7 (coprime with 20) → public key (7, 33). Find d such that e×d ≡ 1 (mod 20) → d=3 → private key (3, 33). To encrypt M=2: C = Me mod n = 27 mod 33 = 29. To decrypt: M = Cd mod n = 293 mod 33 = 2 ✓. RSA's real-world security comes from using primes hundreds of digits long — factoring their product back into p and q is computationally infeasible.
