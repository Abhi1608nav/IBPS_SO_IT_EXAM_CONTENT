Where Programming actually sits in the exam

IBPS SO IT Officer has three stages — Prelims (qualifying), Mains (merit-deciding), and Interview. Programming, OOP, and Data Structures live entirely inside the Professional Knowledge paper, alongside DBMS, Networking, OS and Software Engineering.

📝 Prelims qualifying

English, Reasoning, Quantitative Aptitude — and as of the 2026 revised pattern, a Professional Knowledge section too, each sectionally timed. Prelims marks are not counted toward final merit.

🎯 Mains merit

Entirely Professional Knowledge — objective + a couple of descriptive questions from IT/CS subjects. This is where Programming and Data Structures questions carry real weight.

🗣️ Interview 20%

Technical questions on OOP, DS, DBMS and networking are common follow-ups — final merit is Mains 80% + Interview 20%.

Professional Knowledge — approximate topic emphasis

DBMS and Networking have historically carried the heaviest weightage, but Data Structures and OOP/Programming together reliably contribute a solid, scorable chunk — and are easier to master quickly since they reward conceptual clarity over memorisation.

Data Structures syllabus

The core DS syllabus is language-agnostic — the same tree, stack or sort question could be phrased using C, C++, Java or plain pseudocode. Click each topic to expand.

01Arrays & Basic Terminology
▾
Data types & classification, single and multi-dimensional array representation, address calculation for row-major / column-major order, sparse matrices.
  • Row-major address formula: Base + W × (i × N + j)
  • Common trap: off-by-one errors in index-based questions
02Stack
▾
LIFO structure — array & linked implementation, push/pop/peek, overflow & underflow conditions.
  • Applications: expression evaluation (infix→postfix), recursion, backtracking, undo operations, balanced-parenthesis checking
  • Frequently asked: "which structure is used internally for function calls / recursion?" → Stack
03Queue
▾
FIFO structure — array & linked implementation.
  • Circular Queue — avoids wasted space by wrapping REAR back to index 0
  • Deque — insertion/deletion at both ends
  • Priority Queue — element with highest priority served first (often implemented via heaps)
  • Applications: CPU scheduling, BFS traversal, print spooling
04Linked List
▾
Singly, doubly, circular, and generalized linked lists.
  • Key advantage over arrays: dynamic size, easy insertion/deletion (no shifting)
  • Key disadvantage: no random access (O(n) to reach the k-th node), extra pointer memory
  • Doubly linked list trades extra memory (back-pointer) for O(1) reverse traversal
05Searching & Sorting
▾
Linear search O(n), Binary search O(log n) — requires a sorted array.
  • Bubble / Selection / Insertion Sort — O(n²), simple, stable (bubble & insertion), used for small/near-sorted data
  • Quick Sort — average O(n log n), worst O(n²), in-place, not stable
  • Merge Sort — guaranteed O(n log n), stable, needs extra space
  • Heap Sort — O(n log n), in-place, not stable, built on a binary heap
  • Radix Sort — non-comparison based, O(nk) for k-digit numbers
06Hashing
▾
Hash tables, hash functions, and collision resolution.
  • Collision handling: chaining (linked lists at each bucket) vs open addressing (linear/quadratic probing, double hashing)
  • Performance degrades as the load factor (n/table size) rises
07Trees
▾
Binary Tree, Complete Binary Tree, Extended (2-tree), array & linked representation, Binary Search Tree, AVL Tree (self-balancing, rotation-based).
  • Inorder (L-Root-R) on a BST → elements in sorted order — a favourite exam fact
  • Preorder (Root-L-R) — used to clone/serialize a tree
  • Postorder (L-R-Root) — used to safely delete a tree
  • Height of a balanced binary tree with n nodes: O(log n)
08Graphs
▾
Representation via adjacency matrix (O(V²) space) or adjacency list (O(V+E) space).
  • BFS — uses a Queue, finds shortest path in unweighted graphs
  • DFS — uses a Stack (or recursion), used for topological sort, cycle detection
  • Minimum Spanning Tree — Prim's and Kruskal's algorithms, both greedy

Object-Oriented Programming concepts

This is the single most-repeated theme in the Programming section — usually as terminology-matching or "which concept does this describe" questions, framed around any of the three languages.

Encapsulation

Bundling data (attributes) and the methods that operate on it into a single unit (a class), while restricting direct outside access — usually via access specifiers.

class Account { private double balance; // hidden from outside public double getBalance() { return balance; } }

Abstraction

Showing only essential features while hiding implementation detail. Achieved via abstract classes or interfaces — the user knows what a method does, not how.

abstract class Shape { abstract double area(); // what, not how }

Inheritance

A class (child) acquires properties and behaviour of another class (parent) — promotes code reuse. Types: single, multiple, multilevel, hierarchical, hybrid.

class SavingsAccount extends Account { // inherits balance-handling behaviour }

Exam trap: Java does not allow multiple inheritance through classes (only via interfaces) — C++ and Python both allow it directly through classes.

Polymorphism

"Many forms" — a single interface, multiple behaviours.

// Compile-time (overloading) int add(int a, int b); double add(double a, double b); // Run-time (overriding, via virtual/base methods) class Animal { void sound() {} } class Dog extends Animal { void sound() { /* barks */ } }

Constructor vs Destructor

A constructor shares the class name, has no return type, and runs automatically on object creation (can be overloaded). A destructor (C++: ~ClassName()) runs when the object is destroyed — Java/Python instead rely on garbage collection, so there's no explicit destructor call.

Static vs Dynamic Binding

Static binding resolves a call at compile time (overloading, non-virtual calls). Dynamic binding resolves it at runtime based on the actual object type (overriding, virtual functions) — this is what enables runtime polymorphism.

Access Specifiers

public — accessible everywhere. private — only within the class. protected — class + subclasses. Java additionally has a package-private default; Python uses naming convention (_protected, __private) rather than true enforcement.

Overloading vs Overriding

Overloading — same method name, different parameter list, same class, resolved at compile time. Overriding — same signature, subclass redefines parent's method, resolved at runtime.

C++ vs Java vs Python

The exam doesn't commit to one language — it borrows syntax cues from all three and expects you to recognise which feature belongs to which. This is the highest-yield "quick win" topic in Programming.

account.cpp
// Compiled to native machine code · manual memory (new/delete) · pointers
#include <iostream>
using namespace std;

class Account {
private:
    double balance;
public:
    Account(double b) { balance = b; }   // constructor
    ~Account() { }                       // destructor (explicit)
    double getBalance() { return balance; }
};

int main() {
    Account* acc = new Account(500.0);   // pointer + heap alloc
    cout << acc->getBalance();
    delete acc;                          // manual free — no GC
    return 0;
}
Account.java
// Compiled to bytecode → runs on JVM (JIT) · Garbage Collected · no pointers
import java.util.*;

public class Account {
    private double balance;

    public Account(double b) { balance = b; }   // constructor
    // no destructor — GC reclaims memory automatically

    public double getBalance() { return balance; }

    public static void main(String[] args) {
        Account acc = new Account(500.0);
        System.out.println(acc.getBalance());
    }
}
account.py
# Interpreted (CPython) · dynamically typed · indentation defines blocks
class Account:
    def __init__(self, balance):   # constructor
        self.balance = balance

    def get_balance(self):
        return self.balance

if __name__ == "__main__":
    acc = Account(500.0)
    print(acc.get_balance())

How questions actually get asked

Programming/DS questions in IBPS SO rarely ask you to write code from scratch. They cluster into a handful of recurring formats:

01

Terminology fill-in-the-blank

A definition is given; you identify the matching OOP/DS term.

"____ is the OOP feature by which one class acquires the properties of another." → Inheritance
02

Odd-one-out / classification

Pick the item that doesn't belong to a given group (e.g., which of these is not a sorting algorithm / not a linear data structure).

Array, Stack, Tree, Queue — which is NOT linear? → Tree
03

Complexity / Big-O identification

Time or space complexity of a named algorithm or operation — usually a direct recall, not a derivation.

Time complexity of Binary Search on a sorted array of n elements → O(log n)
04

"Which structure fits this scenario" application

Maps a real use-case (recursion, undo, BFS, scheduling) to the correct underlying data structure.

Which structure is used internally to implement function-call recursion? → Stack
05

Cross-language feature comparison

Tests whether a specific language supports a given feature — a common trap around multiple inheritance, pointers, and operator overloading.

Which language does NOT support multiple inheritance through classes? → Java
06

Traversal / output-based

A small tree or short snippet is shown, and you determine an output — inorder/preorder sequence, loop output, or final variable value.

Which traversal of a BST returns elements in sorted order? → Inorder

Preparation strategy

Programming/DS is one of the fastest sections to become reliably strong in — it rewards concept clarity far more than depth of coding practice.

1

Concepts over syntax

You won't be asked to write a working program. Focus on definitions, comparisons, and "what does this achieve" style understanding across all three languages rather than memorising exact syntax in any one.

2

Don't skip any one language

Since questions borrow syntax cues from C++, Java, and Python interchangeably, build baseline familiarity with all three rather than mastering just the one you already know.

3

Drill the comparison table until it's automatic

Memory management, pointers, multiple inheritance, and platform dependency are the four traps that reappear most often across past papers.

4

Data Structures: know the "why", not just the "what"

For every structure, be able to answer: what's it good at, what's it bad at, and what's the go-to real-world use case (stack→recursion, queue→BFS, hash table→lookups).

5

Weight your remaining time correctly

DBMS and Networking still carry the most marks in Professional Knowledge — treat Programming/DS as a high-ROI section to lock in fully, not the sole focus of your prep.

6

Always check the current-year notification

IBPS revises exam patterns fairly often (Professional Knowledge was added to Prelims in the 2026 cycle) — confirm section-wise weightage and question counts against the latest official notification before finalising your plan.
